# LISA 项目方案

基线日期：2026 年 10 月 22 日。文档更新：2026 年 10 月 23 日。状态：需求设计中，应用尚未实现。

LISA 为希望获得文学创作成果、但不喜欢操作传统 AI 写作工具的用户，以及希望从 AI 交流中获得基本情感满足的用户，提供持续的朋友式交流与自主文学创作。交流与关系体验优先，作品质量是必须守住的要求。

本方案是当前产品规则的唯一主文档，供产品设计与后续开发使用。“已确认”来源于用户明确选择；“建议默认值”用于补齐执行边界，尚未逐项确认；“实现建议”描述尚可调整的实现细节。整体架构与工具栈已按 D12 确认，见“技术架构与工具栈”。后续问题与状态统一维护在 [待决策清单](PENDING_DECISIONS.md)，过度设计的历史依据见 [设计评审](DESIGN_REVIEW.md)。

## 产品定位与已确认决策

| 事项 | 已确认的首版决策 |
| --- | --- |
| 主要入口 | QQ 私聊，采用 CQHTTP 接入；网页是完整创作工作台 |
| 用户范围 | 初期面向成年人，允许将用户真实经历用于创作 |
| 关系定位 | 从朋友开始，允许关系自然发展 |
| LISA 身份 | 各用户拥有独立发展的 LISA，从通用 prompt 开始，按交流与反馈形成差异 |
| 虚拟生活 | 少量稳定背景与持续事件，通过长期记忆维持连续性 |
| 创作关系 | LISA 是产品叙事中的作者，用户提供权威意见；网页直接修改具有最高内容优先级 |
| 项目数量 | 一个用户一个项目，保留未来多项目扩展能力 |
| 创作结构 | 首版维护一条作品内容线，不做创作分叉、分支比较或主线切换；保留普通版本记录与恢复 |
| 编辑责任 | 用户维护改稿后的语义一致性；生成期间编辑仅作网页提示，不实现并发编辑冲突处理 |
| 作品类型 | 项目可以是 LISA 自己的日记或小说等其他文学作品；首版不同时维护日记与小说两个创作项目 |
| 自主程度 | 满足用户权威意见后，AI 可以自主决定文学作品中的内容 |
| 创作节奏 | 先交流至基本内容达成一致，再按计划小步推进；控制单次篇幅及累计进度，保持可重写性，不急于一次完成整部作品 |
| 停止条件 | 用户连续 24 小时未回复时全局暂停自主行为，直到用户回复；已开始任务正常完成，网页单次手动重写仍可执行 |
| Agent 结构 | 主 Agent 负责交流与委托，作者 Agent 负责作品，角色 Agent 按需参与 |
| 上下文目标 | 缩短上下文，减少注意力漂移，避免把全部历史交给每个 Agent |
| 用户可调内容 | 正文、设定、角色 Agent prompt、检索策略和长期记忆 |
| 网页美术 | 采用已确认的“私人书房”设计；后续前端开发遵循 [前端美术与界面规范](FRONTEND_DESIGN.md) 及原型参照 |
| 模型 | 平台提供，首版不开放用户选择模型 |
| 部署目标 | 短期由项目方部署并面向公众，长期支持个人自行部署 |
| 规模与架构 | 最多千人使用规模，采用模块化单体、后台 worker 和统一数据库，不建设大流量架构 |
| 延迟与成本 | 允许较长响应时间；人均成本尚未确定，需要记录实际消耗 |

“LISA 是作者”描述产品体验，不在本方案中作法律权属约定。

## 用户与项目边界

首版的逻辑关系是：一个用户拥有一个 LISA 实例，一个 LISA 实例维护一个项目，项目包含一条作品内容线及其历史版本。章节不构成独立项目；备选情节可以作为讨论素材，不建立独立创作分支。

LISA 的人格、虚拟生活和与用户的关系记忆独立于作品内容。小说项目中的 LISA 仍可拥有日常生活背景，但不会因此额外生成一个日记项目。日记项目记录 LISA 的视角与虚拟生活，不默认成为用户本人的现实日记。

日记中的比喻、想象及未采用草稿不自动成为虚拟生活事实；已经采用的生活事件应与主 Agent 的记忆保持一致。

正常创作中新事件的采用与同步流程待 D06 细化。网页改稿后的相关生活事件、设定与记忆由用户维护，不要求系统自动识别并同步语义变化。

实现建议：保留独立的用户、LISA 实例和项目标识，首版限制每位用户只有一个项目。不实现项目切换、跨项目检索或自动判断消息属于哪个项目。不同用户的记忆、作品、角色和虚拟生活进展相互隔离。

项目类型长期变更的流程未定义。首版不提供自动将小说转换为日记等操作，不因聊天中的临时想法自动重建或覆盖项目。

## 核心使用流程

1. 用户从 QQ 开始与 LISA 交流，并按需绑定网页账户。
2. LISA 以自然聊天分享观察或创作想法，例如“我有一个想法想和你聊聊”，逐步提出自己的作品方向。
3. 用户给出评价与建议；主 Agent 理解当前情绪、创作要求和偏好，不催促用户补齐问卷。
4. 与用户交流至作品基本内容达成一致后，主 Agent 将范围有限的创作意图交给作者 Agent；作者结合已有设定小步推进作品，按需调用角色 Agent。
5. LISA 在适当时机分享进展或片段，用户可以在网页阅读、修改正文、查看版本或编辑设定。
6. 后续任务使用已保存的内容；改稿涉及的设定、剧情状态和记忆一致性由用户维护。
7. 用户连续 24 小时未回复后全局暂停自主行为；用户回复后，先吸收新消息，再判断后续交流与创作安排。

首次交流可以只讨论想法和初步方向，不急于生成正文。作品基本内容达成一致后，才开始范围有限的创作；不必等全部世界设定和人物资料齐备，也不要求每次聊天都产出作品。基本共识来自交流中的实际反馈，不能把用户沉默或暂未反对当成同意；这不要求用户逐段批准后续正文。

用户未回复创作讨论且仍在 24 小时活跃时限内时，LISA 可以先为未决内容形成可修改的默认设计，作为自己的暂定方案保留，并在间隔一段时间后开启新话题。默认设计不等于用户已确认，也不直接触发正文创作；用户之后可以重提旧话题并修改此前的暂定决定。达到 24 小时后不再定时开启新话题。具体联系边界见“作息学习与主动联系”。

## 交流与人格

LISA 的表达应口语化、具体，并自然延续上下文。情绪价值来自认真回应、记住细节、表达自己的看法和共同经历，不依赖固定夸赞模板。

| 信息层 | 内容 | 建议更新方式 |
| --- | --- | --- |
| 核心人格 | 身份、基本性格、价值倾向、稳定生活背景 | 保持稳定，修改留存版本 |
| 相处偏好 | 称呼、语气、消息长度、幽默方式、提问频率 | 根据明确反馈和持续证据小幅调整 |
| 关系与经历 | 讨论、约定、分歧、虚拟生活事件 | 随交流积累，并可纠正 |

建议默认值：不允许模型因一次反馈自动重写整份核心 prompt；优先更新局部偏好与记忆。反馈的原始依据应可追溯。关系自然发展，不设亲密度积分、强制升级路线或必须发生的亲密事件。

具体初始人格、固定背景及首次交流示例待 D07 决定。

交流要求：

- 先回应用户当下关心的内容，允许整段交流不推进创作。
- 普通闲聊是了解用户阅读习惯与创作偏好的重要来源；从自然交流中积累依据并调整创作，不要求用户专门填写偏好问卷。
- 优先问少量真正有价值的问题，通常一轮只追问一个主要问题。
- 可以提出自己的审美判断，但用户明确要求与网页编辑最终约束创作。
- 不把未回复解释为用户厌烦、拒绝或关系恶化，不用内疚式措辞催促回复。
- 将用户明确表达、AI 推测、虚拟经历和作品内容区别保存。
- 产品介绍和人物资料说明 LISA 及其生活为虚拟设定，日常交流无需反复打断叙事说明。

## 用户意见与创作权威

| 输入 | 处理方式 |
| --- | --- |
| 明确约束，例如不允许某角色死亡 | 保存为当前有效约束，后续创作遵守 |
| 多次出现的偏好 | 形成可修正的偏好记录，区别于硬性约束 |
| 普通闲聊中体现的阅读习惯与创作倾向 | 结合上下文推断偏好，保留依据与不确定性，用于调整后续创作；不自动升级为用户明确要求 |
| 针对某段正文的评价 | 优先作用于对应段落，不无条件推广到全书 |
| 假设、玩笑、备选剧情 | 保留为讨论或候选素材，不立即成为正式事实 |
| 未回复时由 LISA 形成的默认设计 | 保留为可修改的暂定方案，注明由 LISA 暂定，不记成用户确认；用户后续重提时可修正 |
| 网页直接编辑 | 成为所编辑对象的有效版本，AI 不自行撤销 |

分类与一般整理交给 AI。只有含义确实不清楚、影响又较大时，才自然追问。用户提出重大剧情要求也不需要经过多层批准流程。

已确认（2026 年 10 月 23 日）：主 Agent 应从所有交流中理解用户，普通闲聊同样可用于推断阅读习惯、题材兴趣、叙事节奏和表达方式等创作偏好，并将相关偏好交给作者以修正后续创作。推断应能随新证据调整，区别于明确约束；一次随口评价不应机械推广为整部作品的硬性要求。推测偏好不能覆盖用户明确指令或网页修改，也不单凭推测大面积重写已有正文。闲聊能刷新活跃计时，不代表它确认了尚未达成共识的作品基本内容。

建议默认值：对同一事项，用户较新的明确指令可替代较旧指令，但 AI 不能以推测出的偏好覆盖网页编辑。用户后来明确要求修改网页已定内容时可以执行；不能把旧版本永久锁定而拒绝用户的新意图。

## 自主推进与暂停规则

已确认：LISA 主动推进创作；用户连续 24 小时未回复时，全局暂停该用户 LISA 的自主行为，直到用户回复。暂停按各用户独立计时，不影响其他用户。

以下为已确认的执行规则（D01，2026 年 10 月 23 日）：

| 条件 | 行为 |
| --- | --- |
| 尚未收到首次用户消息 | 不启动自主创作 |
| 距最近有效用户消息不足连续 24 小时 | 基本内容已达成一致时允许按计划小步创作，仍受推进节奏、可重写范围与资源预算限制 |
| 达到连续 24 小时 | 全局暂停新的自主任务及主动联系；已经开始的有限任务正常完成，随后保持暂停 |
| 暂停后收到有效新回复 | 先理解消息并更新相关意见，再重新安排交流与创作；不集中补跑暂停期间的计划 |

已确认：用户主动发来的所有新消息都算有效回复，不限话题或消息形式，普通闲聊同样计入，不以是否涉及创作或能否提取偏好为条件。首版从最近一条有效 QQ 用户消息起计算连续 24 小时；LISA 发言、回执、重复投递、网页浏览和网页编辑不刷新计时，也不自动恢复自主行为。若以后增加网页聊天，再统一接入用户消息规则。

收到有效新回复后，先理解消息、更新相关意见与偏好，再依据当前作品、共识及预算重新安排后续交流和创作，不集中补跑暂停期间错过的计划。恢复活跃不等于立即开始写作，仍遵守 D02 的共识与小步推进要求。

已确认（2026 年 10 月 23 日）：暂停期间，用户可以在网页明确发起一次重写，系统执行完该次手动任务后仍保持自主创作暂停。该任务本身不刷新自主创作的活跃计时，也不触发后续自主任务。网页编辑、手动创作和自主创作恢复应分别处理。

计时应依据可信的消息时间，延迟投递或重放的旧消息不能假装成刚刚回复。具体时间字段与时钟偏差在网关接入验证时确定。

已确认（2026 年 10 月 23 日）：未回复时限是软限制。到期后不再启动新的自主任务，已经开始的有限任务可以正常执行至完成，包括完成该任务所需的作者与角色调用，不因到期强制取消。结果按正常的用户约束与采用规则处理，不仅因跨过时限就转为待检查草稿或禁止采用；任务完成后不自动接续新的自主任务。创作任务以 D02 确定的有限成果为终点，不能以完成当前任务为由无限续写。待执行的定时换题及主动发送不因提前排入计划而获得到期后的执行例外。

已确认（2026 年 10 月 23 日）：24 小时是全局自主行为的暂停标准线，用于避免用户未参与时的额外性能开销。暂停后不再主动联系或定时换题，也不启动默认设计、虚拟生活推进、反思、作息学习及自主记忆整理等后台自主任务。不通过定期调用模型判断是否应该联系来绕过暂停。接收用户新消息和处理用户明确发起的网页操作仍可进行；网页单次手动重写的既定例外保留，执行完不恢复自主行为。

已确认（D02，2026 年 10 月 23 日）：自主创作先与用户交流至基本内容达成一致，再由主 Agent 按计划委托有限任务。触发可来自交流中的新想法、用户明确要求或此前安排的计划步骤；不要求每条消息都写作。未收到新回复但仍在活跃时限内时，可以在已有共识、推进节奏及预算允许的范围内继续。

每次任务以一个范围有限、便于重写的成果为终点，例如一个短场景、一篇篇幅适当的日记或一段局部重写，包含必要的检查与修改。单次篇幅与新增剧情的影响范围都要受控；较大的场景或章节应拆分，不能仅因称为“一个场景”就允许大规模展开。完成后结束该任务，由主 Agent 结合用户意见、作品状态、时限与预算决定后续安排，作者不自行无限接续。

推进节奏应给用户留出消化、纠正和改变想法的空间，不以尽快写完整部作品为目标。除单次任务大小，还要控制尚未获得用户进一步反馈期间的累计推进量，避免连续执行多个小任务后仍产生大面积重写成本。后续内容若依赖尚未达成共识或正在纠正的关键内容，应先交流澄清，再继续相关创作；用户未回复时可先保留默认设计并换话题，不反复追问，也不因已有暂定方案而急于生成依赖它的正文。已有共识范围内仍保留自主创作和采用能力，不增加逐段审批要求。

具体篇幅、任务间隔、累计推进量及调用上限留待试运行确定；控制重写成本是已确认要求，不能仅靠拆小任务或间隔调参绕过。主动联系遵循已确认的 D03 规则。

## 作息学习与主动联系

记录可观察的互动时段、回复长度、话题偏好和近期变化，以调整联系时机和表达方式。将“经常晚间回复”保存为带依据的推测，不升级成未经用户确认的睡眠、职业或情绪事实。

用户明确设置的时区、免打扰时间和联系偏好优先。回复时间不直接用于推断亲密程度。

已确认（2026 年 10 月 23 日）：主动聊天以日常交流为主，核心是 LISA 的虚拟生活，可自然延伸到兴趣、感受与创作想法；作品进展适时分享，不作为主动聊天的中心。不反复追问，不施加回复压力。虚拟生活分享应延续已有背景与经历，继续遵守有限推进及 24 小时全局暂停规则。

已确认（D03，2026 年 10 月 23 日）：用户未回复且仍在 24 小时活跃时限内时，不持续追问同一话题。对于尚未决定的创作内容，先形成可修改的默认设计，保留旧话题及暂定结论；间隔一段时间后主动开启新话题，用户不必先回答旧问题才能继续交流。达到 24 小时后停止主动联系，不再定时开启新话题，也不在后台持续生成话题。用户后续重提旧话题时，应接续原有上下文并允许修改暂定决定，不能以已经换题或已有默认方案为由拒绝。

此规则兼顾用户没看到消息与不知道如何回复的情形，不要求模型判断具体原因，也不能把其中一种原因记成用户事实。默认设计是 LISA 的暂定方案，不是用户授权或已达成的创作共识；不因生成了默认设计、等待时间到达或换了话题就急于生成文章。已有共识内的创作继续遵守 D02 的小步推进与重写成本要求。

已确认（2026 年 10 月 23 日）：在 24 小时活跃时限内，根据已学习的交流习惯选择主动联系与换题时机，同时设置最低联系间隔和频率上限。网页允许用户设置免打扰时段、降低主动联系频率或关闭主动联系；用户明确设置优先于学习结果，24 小时全局暂停线始终有效。最低间隔与频率上限的具体数值留待试运行确定，不允许连续循环生成方案和发送新话题。

自主创作、记忆整理与发送消息分别判断：作品完成不意味着立即发送，多次生成也不意味着多次联系。主动联系的具体频率和免打扰默认时间尚未确定，接入能力与试运行结果确认后配置。

已确认（D03，2026 年 10 月 23 日）：用户明确委托的任务，可以先用自然语言简短回应，完成后告知结果；LISA 自己在后台推进的创作不播报处理进度，有值得分享的内容时再自然交流。网页保留进行中、完成、失败、暂停等任务状态，不要求百分比或逐步骤汇报。主动分享继续遵守联系设置及 24 小时全局暂停规则。

这里的“长任务”仅指单次有限任务的等待时间较长，例如局部重写需要核对前文，或一个短场景需要角色参与及作者整理；不增加一次完成整部作品的任务范围，不改变 D02 的小步推进要求。

## Agent 职责与上下文

| 角色 | 职责 | 必要上下文 | 输出 |
| --- | --- | --- | --- |
| 主 Agent | 与用户交流，维持人格与关系，整理意见，委托作者 | 稳定人格、近期对话、相关用户记忆、虚拟生活状态、创作摘要 | 回复、有限记忆更新、创作委托 |
| 作者 Agent | 维护作品全局、设定与剧情，组织创作，管理角色 | 本次委托、用户约束、当前作品状态、相关世界书和正文 | 草稿、采用后的作品状态更新、给主 Agent 的摘要 |
| 角色 Agent | 提供自身角色的对话、行动与反应 | 角色 prompt、自己的经历与已知信息、当前场景 | 场景建议，由作者选择并汇总 |

日记、短篇或简单场景允许作者直接完成。作者按需要创建角色配置，只有任务涉及该角色时才调用；不要求每个具名角色都有独立 Agent，不让角色继续创建下级 Agent。

主 Agent 在基本内容达成共识后，负责控制委托范围与推进节奏，并考虑自用户上次提供创作反馈以来的累计进度。作者在本次约定的有限范围内完成正文及必要修改；“直接完成”不意味着一次写完整部短篇，也不授权自行扩大为整部作品。影响后续方向的疑问交回主 Agent 自然交流。

主 Agent 将闲聊中发现的相关阅读习惯和创作偏好整理进记忆，并在委托时提供给作者；明确偏好与推测偏好分开表达，作者据此调整后续内容与表现方式，同时遵守用户约束及网页编辑优先规则。

作者维护的设定与状态保存为可检查的数据，不依赖永久增长的模型会话。角色只获得有权知道的信息，其输出不能直接覆盖全局剧情。最终采用的正文和事实由作者统一提交。

满足有效约束时，作者可以自主采用自己的草稿，不要求用户逐章确认。未采用的草稿及角色建议不进入作品事实。首版不设置分支或基于并发编辑冲突的采用流程；用户改稿后的语义关联由用户维护。

采用后何时显示为网页当前正文、怎样区分草稿仍待 D04 细化。任务通知遵循已确认的 D03：用户明确委托的任务完成后告知，自主创作按联系规则适时分享；通知与正文采用分别处理。采用仅作用于用户自己的项目，不表示公开发布。

实现建议：这些 Agent 首先是不同职责的调用与数据配置，不要求独立服务、独立数据库或常驻进程。用户编辑的角色 prompt 和检索配置作用于该角色，不能改变账户隔离及数据访问范围。

## 长期记忆与检索

RAG 在首版服务于两项明确需求：主 Agent 找回与用户的长期记忆，作者和角色找回大规模世界设定与相关剧情。语义检索本身不承担全部人格稳定和事实正确性保障。

| 资料 | 使用方式 |
| --- | --- |
| 稳定人格、明确用户约束、当前任务 | 固定提供精简内容，按任务判断相关性 |
| 最近关系状态与作品状态 | 使用可更新的短摘要 |
| 用户经历、相处偏好、共同交流 | 限定用户后按需检索 |
| LISA 虚拟生活事件 | 保留简要时间线，按需检索 |
| 世界书、旧正文、剧情记录 | 限定项目与有效内容后按需检索 |
| 角色个人记忆 | 进一步限制该角色的知识范围 |

采用关系记忆与作品资料两类逻辑范围即可，不为表中的每类内容建立单独数据库。先限定用户、项目、用途、有效状态与角色知识范围，再进行相似度检索。

记忆至少保留内容、来源、类型、作用范围、有效状态，以及推测的依据或可信程度；不适用的字段不强行填充。用户明确事实、推测、虚拟生活和文学想象必须能区分。虚构的海边独行不能被记成用户曾陪 LISA 去过海边。

正文、设定、明确记忆条目是事实依据，检索索引是可更新的派生数据。用户直接纠正某条记录后，该记录的旧内容停止参与检索，不能仅新增一条相反记录而让二者长期竞争。摘要可以重建，不把摘要视为不可纠正的事实。更新被编辑对象自身的检索文本属于基本保存流程；从正文改动推导其他设定、人物状态、摘要或记忆应如何变化属于语义维护，由用户负责，不建立跨内容的自动一致性修复机制。

用户可查看、纠正、删除、限制记忆用途。排除真实经历的创作用途时，阻止后续作为作品素材使用。删除记忆应同时使对应索引失效；原始聊天、现有正文及备份是否一并删除需单独说明，不能承诺删除一个记忆条目就抹除所有历史。

如果原始聊天仍被保留，已删除或排除的记忆不能在重新整理、重建索引时被自动恢复；需要记录相应排除范围，而不是只删除向量条目。

## 网页工作台与版本

网页功能按能力划分，不要求每个能力都有独立页面。已确认（D11，2026 年 10 月 23 日）：沿用当前“私人书房”原型的视觉与页面结构，以作品、设定与角色、记忆三个主要区域组织工作台，任务状态嵌入相关位置。暖纸色、墨绿、衬线阅读排版、书封与便笺构成统一美术方向；具体配色、布局、组件、响应式和视觉验收依据见 [前端美术与界面规范](FRONTEND_DESIGN.md)，后续实际开发按该规范执行。

此确认仅确立视觉与界面基线，不把示例作品、人物、原型参数或简化交互确认为业务规则，也不决定正式应用技术选型。产品行为仍以本方案与相应决策结论为准。

| 能力 | 首版范围 |
| --- | --- |
| 阅读与正文管理 | 阅读、编辑保存、局部重写、版本查看与恢复 |
| 设定 | 编辑世界书条目、角色资料与有效约束 |
| Agent 配置 | 查看作者和生成的角色，编辑角色 prompt，查看简要参与记录 |
| 检索配置 | 编辑资料范围、召回数量、文本预算等有限参数，恢复默认值，查看实际引用资料 |
| 长期记忆 | 查看来源、搜索、纠正、删除和限制用途 |
| 任务状态 | 查看进行中、完成、失败、暂停，允许取消及重试 |
| 账号与偏好 | QQ 绑定、免打扰时段、降低主动联系频率或关闭主动联系、基础导出 |

首版不开放用户模型选择。角色卡与世界书的精致可视化属于后续体验增强，基础列表与表单足以支持首版管理。

网页修改表达用户的权威内容意图。设定修改默认影响后续创作，不静默重写历史正文。已确认（2026 年 10 月 23 日）：改稿后的语义一致性由用户自己维护，包括相关设定、人物经历、作品摘要与记忆；系统不自动分析修改影响、级联修正这些内容，或等待语义同步完成才允许继续创作。

自主创作暂停期间，网页仍允许用户明确发起单次重写。执行及结果处理遵守正常的用户约束与采用规则，完成后仍保持自主创作暂停。

已确认（2026 年 10 月 23 日）：首版不处理用户编辑时正在生成的并发场景。网页在有创作任务运行时提供轻量提示，例如“正在生成，建议完成后再编辑；修改关联内容请自行核对”，不增加编辑锁、版本冲突检查、自动合并、冲突草稿或额外采用审批。网页编辑优先表示后续创作应遵循用户保存的内容意图，不承诺并发编辑期间的自动保护。

正文保留普通的线性版本记录与恢复能力，供用户查看和找回内容；后续任务读取已保存的内容。基础保存与索引更新不扩展为语义一致性保障。

已确认（D05，2026 年 10 月 23 日）：首版不维护创作分叉，不提供分支比较、主线切换、分支记忆或分支级检索。讨论过的备选情节仍可保留为讨论素材，不能自动作为已采用事实。普通版本历史不构成创作分支。

## 接入与部署边界

QQ 首发采用用户指定的 CQHTTP 方向。CQHTTP 兼容实现、版本和传输方式尚未指定；OneBot 11 兼容可作为接入验证目标，不能在验证前承诺具体网关能力。此前针对 QQ 官方机器人的限制不直接套用于该方案。

首版只实现 QQ 适配。内部保留接收用户消息、发送回复、查询发送结果等小接口，为未来平台扩展留边界，不提前开发通用平台插件市场。

接入验收包括私聊身份识别、网页账户绑定、消息去重、有序处理、连续消息合并策略、发送失败有限重试及主动私聊能力。账号绑定需要验证身份，不能仅凭填写 QQ 号获得他人数据。

主动联系在发送前应遵守用户当前联系设置、免打扰时段、最低间隔、频率上限及 24 小时全局暂停规则；此前安排的换题任务不能绕过之后生效的设置。

明确失败的发送可以有限重试；结果不明时先核对网关状态，无法核对则记录为未知，不盲目重复发送。一次发送失败不应导致重新生成整篇作品。

短期多人托管需要从存储、检索、任务到网页访问均隔离用户数据。长期自行部署优先通过平台凭据与模型配置外置、数据可导出实现，不在首版建设两套不同的产品架构。

已确认（D12，2026 年 10 月 23 日）：项目面向最多千人的使用规模，以单机部署的模块化单体、后台 worker 和统一数据库起步，不按千人同时调用模型或大流量平台设计。并发任务数按模型额度、预算与实测耗时配置，忙时排队即可；用户总数不是已经验证的性能承诺。具体架构与工具栈如下。

## 技术架构与工具栈

已确认（D12，2026 年 10 月 23 日）：用户接受架构建议，同时明确移除首版分叉、将改稿语义一致性交给用户、仅提示生成期间编辑，并要求避免过度防御和过度设计。以下为按这些边界收缩后的技术基线，尚未开始应用实现。

部署结构为：网页与 QQ 适配接入同一后端应用；API 和后台 worker 共用业务代码，作为两个进程运行；业务数据、记忆、检索索引及持久化任务统一保存于 PostgreSQL。主、作者与角色 Agent 是职责、prompt、上下文和可用工具的组合，不是独立服务。

| 层面 | 已接受的工具与方向 | 实施边界 |
| --- | --- | --- |
| 网页 | React + TypeScript + Vite | 单页工作台，沿用私人书房规范 |
| 正文编辑 | Tiptap 开源核心 | 保存结构化正文与普通版本，提取文本用于检索；不实现协作编辑和分叉 |
| 后端 | Python + FastAPI + Pydantic | API、业务逻辑和模型输出校验 |
| 数据访问 | SQLAlchemy + Alembic | 常规事务与数据库迁移 |
| 数据与检索 | PostgreSQL + pgvector | 一套数据库，按用户和用途过滤；先用精确向量检索，必要时再优化 |
| 后台任务 | Procrastinate | 持久化有限任务、延迟执行与有限重试；实施时验证重启恢复行为 |
| 模型调用 | 供应商 SDK + 薄适配层 | 平台统一配置模型，具体供应商与模型通过中文对话及写作评测确定 |
| 部署 | Linux + Docker Compose | 单套 API、worker、数据库与反向代理；QQ 网关环境按 D08 验证 |
| 验证 | pytest + Playwright | 业务规则与网页主要流程；不设置大流量压测目标 |

后端按身份与接入、对话与关系、创作与版本、记忆与检索、任务调度、模型与消耗划分模块，保持小接口。不引入微服务、Kubernetes、分库分表、缓存集群、独立向量服务或通用 Agent 编排平台，不为未来分支预建数据结构。

数据以用户、LISA 实例、项目、章节及线性版本、设定与约束、角色配置、记忆及来源、任务和模型调用记录为核心。任务保留目标、输入内容引用、结果、状态和消耗，足以排查失败与防止重复采用；不建设内容依赖图或完整事件溯源系统。版本用于历史查看与恢复，不作为并发改稿的提交门禁。

模型负责理解交流、提出有限任务、生成内容及候选记忆；程序负责归属与用途权限、任务上限、24 小时暂停、联系设置和保存。上下文采用稳定人格与有效约束、简短当前摘要、按需检索三层结构。角色仅得到自己的已知信息，用户编辑 prompt 或检索参数不能扩大权限。

后台按用户保存活跃时间及下次计划时间，通过普通定时检查触发工作，不为每位用户维持常驻 Agent。模型调用设置全局并发上限及有限调用预算，同一作品的创作任务按顺序执行；此调度不锁定网页编辑。聊天与创作采用不同任务类型，聊天不必等待该用户的长篇生成结束。到期停止新自主行为，已开始的有限任务正常完成；网页单次重写保持独立来源。

保留与实际故障直接相关的基础处理：账户隔离、消息去重、任务状态持久化、有限重试、重复采用防护、发送状态记录和备份。QQ 发送失败只重试发送，不重新生成内容；结果未知则记录未知。日志和消耗记录以任务为单位，不额外建设复杂运维平台。

记忆直接纠正或删除后，使对应条目与索引失效，并保留来源排除记录，防止重新提取复活；这与用户手动改稿的语义维护分开。原始聊天、既有正文及备份的删除范围仍待 D10。运行数据、凭据和备份与源码分离，提供迁移所需的基础导出。

实现重点收敛为自然交流与人格稳定、中文文学质量、有效记忆与角色知识范围、有限任务和暂停调度、QQ 接入可靠性及模型成本。分支一致性、改稿影响分析和并发编辑冲突不再作为首版研发难点或验收目标。按下面三阶段交付，用多日试用和代表性任务测量质量、耗时、排队与消耗，不虚构千人容量结论。

## 首版边界与交付顺序

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| 连通基础闭环 | QQ 私聊、独立 LISA、账户绑定、单项目、主 Agent 调作者、网页阅读编辑 | 交流达成基本共识后能形成有限篇幅的正文，网页修改能影响下一次创作 |
| 补齐连续使用 | 长期记忆、世界书检索、虚拟生活、相处偏好调整、自主任务与暂停 | 跨日连续交流不混淆事实，暂停与恢复正确 |

以上是同一首版的开发顺序。数据隔离、基本保存、版本记录及任务有限执行从相关能力首次引入时建立；用户手动维护改稿语义，不增加自动一致性修复或并发编辑验收。

首版不做多项目切换、创作分叉与分支比较、主线切换、多人共写、公共作品社区、多平台同时上线、用户模型市场、改稿语义自动同步、并发编辑冲突处理、持续自主角色社会、复杂虚拟世界模拟、关系积分系统和通用 Agent 编排画布。

## 验收场景

1. 用户自然聊天时，LISA 可以表达具体想法并接住情绪，不连续要求填写创作资料；用户能感知她有稳定身份与创作兴趣。
2. 两位用户分别交流后，各自的 LISA 形成不同记忆，任一人的内容不能在另一人的检索、页面、任务或角色上下文中出现。
3. 日记项目只维护日记作品；小说项目的虚拟生活只作为背景与记忆存在，不额外创建日记作品。
4. 作者在无角色 Agent 时能完成日记；复杂场景可以调用角色，角色不会获得其不知道的剧情秘密。
5. 用户明确的创作约束在较长交流后仍有效；直接纠正或删除记忆后，该条目的旧内容不再被检索或重新提取。正文改动所涉及的其他设定、摘要和记忆由用户维护，不以自动语义同步作为验收要求。
6. 用户连续 24 小时未回复后，全局停止启动该用户的自主任务及主动联系，包括创作、默认设计、定时换题、虚拟生活推进和自主记忆整理；已排定但未执行的话题不会在暂停后继续生成或发送，也不定期调用模型判断是否恢复。已经开始的有限任务正常完成，结果仍遵守用户约束与采用规则，完成后不自动接续任务。暂停期间网页单次手动重写正常执行且不恢复自主行为。重复事件不恢复，真实新回复可以恢复，其他用户不受影响。
7. 用户可保存正文并查看、恢复历史版本，后续任务读取保存后的内容。运行创作任务时网页提供编辑提示；用户自行维护关联内容，不测试或承诺并发改稿自动保护。
8. 作品只有一条内容线，界面不提供分叉、分支比较或主线切换；普通版本记录不产生新的独立故事线。
9. 用户修改角色 prompt 或检索范围后，对后续调用生效，并可恢复配置；无法扩大到其他用户的数据范围。
10. 消息重复投递、任务重试和服务重启不会重复采用正文或无限发送消息；失败与消耗可以查看。
11. 通过连续多天试用评价语气自然度、记忆准确性、被理解的感受，以及作品连贯性、表达质量和对用户意见的遵循程度。自动检查不能替代作品质量的人工评价。
12. 只有初步想法、尚未达成基本共识时，LISA 继续交流而不抢先生成正文。达成共识后按有限范围创作，未收到新回复时也不通过连续小任务快速写完整部作品；用户纠正或改变关键内容时，先澄清受影响方向，再继续相关创作。结合单次篇幅、累计进度及修改波及的正文范围，评估重写成本是否可控，同时不要求用户逐段审批。
13. 用户未回复创作讨论且仍在 24 小时活跃时限内时，LISA 为未决内容保留可修改的默认设计，按最终确定的联系间隔和边界开启新话题，不反复追问旧问题，也不因此急于生成文章；到期后遵守全局暂停规则。用户之后重提旧话题时能找回上下文、修改暂定决定；默认设计不被记成用户确认，未回复的原因不被擅自认定。
14. 用户通过普通闲聊或其他形式的新消息回来时，同样刷新活跃计时；系统先理解消息、更新意见，再重新安排后续行为，不集中补跑旧计划。闲聊中有依据的阅读习惯与创作偏好能够影响后续作品，推断可被纠正，不能覆盖明确要求或网页编辑，也不能把普通闲聊误当成对未决创作方向的确认。
15. 活跃期内，主动联系参考已学习的交流习惯，并遵守配置的最低间隔与频率上限。用户在网页设置免打扰、降低频率或关闭主动联系后，后续发送遵守新设置，已排定的换题任务也不能绕过；学习结果不能覆盖用户设置或 24 小时全局暂停规则。
16. 连续交流中，主动话题以围绕 LISA 虚拟生活的日常聊天为主，创作想法和作品进展自然融入；不会每次联系都索要创作意见，也不会因用户未回复而反复追问或施压。
17. 用户明确委托耗时任务时，LISA 可先自然回应，完成后告知结果；自主创作不逐步播报，按联系规则适时分享有价值的内容。网页显示任务状态，无需百分比或逐步骤汇报。

上述为待实施的验收要求，不代表测试已经通过。

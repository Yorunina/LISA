# LISA 首版设计评审

评审日期：2026 年 10 月 22 日。评审对象：当前产品讨论及 [项目方案](PROJECT_PLAN.md)，不涉及应用代码审查。

文档状态：历史评审快照。2026 年 10 月 23 日补充治理说明，以下判断保留评审时的背景。当前规则以项目方案为准；未决问题统一见 [待决策清单](PENDING_DECISIONS.md)，不在本文件维护第二份待办。

后续决定说明（2026 年 10 月 23 日）：用户已取消首版创作分叉，指定改稿语义一致性由用户维护，生成期间编辑仅作网页提示，并接受最多千人规模的精简架构。以下关于“必须保留分支”、自动语义同步、并发编辑冲突保护的旧结论已被 D04、D05、D06、D12 替代；到期任务的旧处理建议已被 D01 的软限制规则替代。正文保留用于追溯，不作为现行实施或验收要求。

结论：核心产品范围可以成立，复杂度主要集中在 Agent 运行方式、人格更新、分支状态和后台自治。首版应保留用户已明确要求的能力，通过按需调用、有限任务和基础工作台降低实现成本。无需把多 Agent、多类记忆和多平台扩展分别实现成大型独立系统。

以下精简边界已作为设计约束或建议反映到项目方案。处理状态为“已记录到方案，尚未实现或验证”；具体推荐仍需按项目方案的状态标记理解，不因出现在评审中就代表用户已确认。

当前范围中实际成本最高的是分支与角色记忆的一致性、用户编辑后的状态同步，以及长期交流的记忆质量。它们来自已经确认的需求，不能仅靠减少 Agent 数量消除。下表也列出需要防止的扩展方向；常驻角色群、微服务、关系积分等并未被用户要求，不代表项目已存在这些实现。

## 过度设计检查

| 设计点 | 判断 | 首版处理 | 代价与边界 |
| --- | --- | --- | --- |
| 持续运行大量角色 Agent | 过度设计 | 保存角色配置，涉及场景时按需调用，由作者统一采用结果 | 不提供所有人物持续离线生活的模拟 |
| 角色继续创建角色 Agent | 无明确需求 | 仅作者创建角色配置，角色不递归创建下级 | 保留作者集中组织角色的方式 |
| 独立编辑 Agent 或审核 Agent | 暂无必要 | 作者在同一任务中完成必要校验，程序检查权限、版本与状态 | 复杂质量问题以后再评估专用角色 |
| 自动不断重写整份人格 prompt | 容易造成漂移 | 核心人格稳定，主要更新偏好、经历与局部配置 | 个性变化较慢，但更容易追溯和纠正 |
| 大型虚拟世界和自治生活 | 超出用户选择 | 少量固定背景、持续事件和简要时间线 | 不提供完整生活模拟器 |
| 亲密度积分和阶段升级 | 不符合自然关系目标 | 只记录实际反馈、约定与相处偏好 | 无等级式关系成长界面 |
| 每类记忆一套数据库 | 过度设计 | 两类逻辑范围加类型、权限、有效状态及分支字段 | 仍需仔细维护检索过滤 |
| 通用自定义检索编排 | 过度设计 | 开放资料范围、召回数量和文本预算等有限参数，提供默认恢复 | 暂不支持任意脚本或检索插件链 |
| 分支自动合并和复杂图编辑器 | 超出首版需要 | 分叉、版本或正文比较、选定主线；列表即可 | 合并内容由用户编辑或以后提出专门能力 |
| 各功能都建独立管理中心 | 易膨胀 | 作品、设定与 Agent、记忆三个主区域，任务状态就地显示 | 不提供通用 Agent 运维控制台 |
| 提前实现多项目与平台路由 | 过度设计 | 独立标识及小适配接口，首版一个项目、一个 QQ 适配 | 不实现跨项目自动识别 |
| 微服务及分布式 Agent 编排 | 缺少规模依据 | 优先单一后端和持久化有限任务，按实际负载再拆分 | 具体并发容量需实测 |

## 不应为了精简而删除的能力

| 能力 | 必须保留的原因 | 最小实现边界 |
| --- | --- | --- |
| 主 Agent 与作者分工 | 用户明确要求，交流与长篇创作需要不同信息 | 不同调用职责，不必不同服务 |
| 角色 prompt 与检索设置 | 用户明确要求工作台可干预角色 | 基础表单、有限参数、恢复默认 |
| 关系记忆与世界书 RAG | 产品连续性与长文本创作的明确需求 | 可追溯条目、检索、失效处理和权限过滤 |
| 分支比较 | 用户明确要求比较结局 | 快照与分叉记录、文本比较、选主线 |
| 用户数据隔离 | 首版面向公众托管且每人独立 LISA | 存储、检索、任务、页面一致验证归属 |
| 网页编辑与版本检查 | 网页修改最高优先级，长任务可能晚于编辑完成 | 输入版本、提交检查、冲突草稿 |
| 暂停规则与资源上限 | 用户规定一天未回复停写，自主任务不能无限运行 | 任务入口与提交检查、有限调用、可暂停 |
| 简要任务持久化 | 较长生成可能跨服务重启或发送失败 | 状态、输入版本、结果和重试记录 |

精简不能把首版退化为普通聊天机器人，也不能把分支、角色配置和检索设置全部推迟到以后版本。

## 一致性问题与修正

### 语义检索无法替代稳定人格与有效约束

若把所有信息均放进检索池，当前任务可能没有得到必须遵守的核心内容。方案采用固定的精简人格与有效约束、当前状态摘要、按需检索三种入口。上下文预算应先保障当前任务的有效要求，旧正文和长世界书按相关性补充。

这不要求新增记忆 Agent 或复杂知识图谱，优先把输入来源和失效规则做清楚。

### 用户事实与虚拟生活容易混写

LISA 的日常、用户真实经历、虚构作品和试探性设想都可能使用第一人称表达。必须记录内容类型与来源；作者虚构不能反向变成用户事实。不是日记项目时，虚拟生活仍能存在，但不额外产生日记作品。

### 删除记忆后重新提取可能使其复活

只删除检索索引而保留全部提取来源，后续整理可能再次生成同一记忆。方案要求删除或排除规则在重建时继续生效，并明确记忆、原始聊天和既有正文的删除范围。首版需要可追溯的排除记录，无需建设复杂的数据治理平台。

### 网页修改后仅保存正文仍不足以生效

旧摘要、旧检索条目和执行中的生成可能继续引用被改掉的内容。方案要求编辑后使冲突派生资料失效，并在任务采用结果前检查版本。无需一开始引入完整事件溯源或分布式事务系统，但不能只用“最后写入覆盖”处理冲突。

用户后来明确的新要求仍可改变此前编辑；最高优先级防止 AI 擅自覆盖，不冻结用户自己的创作权。

### 分支隔离不能只靠角色 prompt

角色指令中写“不知道另一结局”不足以代替资料范围限制。应在检索和任务输入时限定分支，分叉前共享历史，分叉后分开记录状态。主 Agent 可记得讨论过其他结局，但明确其未被当前主线采用。

这不需要为每个分支创建完整用户、LISA 实例和全部角色数据库。

### 一天未回复是执行边界而不是提醒文案

模型自行判断时间或仅在任务开始时检查，会遗漏长任务跨过暂停时间的情况。方案建议以连续 24 小时为明确边界，任务入口及结果采用均检查；无法取消的返回结果先存草稿。消息去重与可信时间保证旧事件不会错误恢复创作。

暂停后是否允许主动联系以及网页操作是否恢复计时仍是建议默认值，不标成用户已经确认的需求。

### 后台自治需要结束条件

“只要不到一天就持续写”可能不断消耗模型并推进远超当前交流范围的内容。每次委托必须有小阶段目标，完成即结束，等待下一触发；同时限制调用次数与 token。无需建立复杂计划系统，也不让模型自行无限排程。

### 可编辑 prompt 不应改变权限边界

用户有权调整自己角色的表现与检索偏好，但 prompt 无权扩大账户访问范围。隔离规则由应用执行，用户编辑仅作用于其自己的数据和角色。无需添加多层审批，只需明确配置字段与访问校验。

### CQHTTP 接入不能沿用官方机器人假设

用户选择的是 CQHTTP 方向。方案不继承之前对官方机器人主动消息限制的推断，也不假设所有 CQHTTP 兼容实现具有完全相同的事件与行为。具体网关确定后做一次接入验证，再冻结协议字段与重试规则；不提前编写多个平台适配器。

## 精简后的实现方向

首版可以由一个网页工作台、一个后端应用、一个 QQ 适配层及可持久化的后台任务处理组成。Agent 是业务职责，记忆类型是数据范围，分支是版本关系，不天然对应独立基础设施。

模型由平台配置。先记录每次任务的输入规模、调用量、耗时、结果及消耗；试运行后再决定预算和是否需要更复杂的模型路由。首版不建设用户模型选择市场或计费套餐系统。

先打通“聊天、委托写作、网页修改、下轮采用修改”的闭环，再补齐跨日记忆、自主暂停与恢复，最后完成角色配置和分支工作台。数据隔离与版本一致性随相关能力一同实现，不能留到上线前集中补救。

## 风险与待验证事项

- 陪伴体验和文学质量需要连续试用评价，架构分工不能证明效果。
- 角色 Agent 是否改善具体场景质量需要实测，不以调用角色数量作为质量指标。
- 回复时段只能支持谨慎的作息推测，需要允许用户纠正。
- 主动联系频率、暂停后的联系策略及有效回复的边界需要冻结后再验收。
- 具体 CQHTTP 网关、身份绑定与发送结果语义需要接入验证。
- 模型、存储方案、并发能力及人均成本尚未确定，不能宣称已满足性能或成本目标。
- 原始聊天和备份的保留、删除范围需在公众托管上线前明确。

此次评审仅完成需求与设计收敛；没有实现应用、接入 QQ、调用模型或执行功能验收。

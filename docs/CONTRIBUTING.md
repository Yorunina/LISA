# Git 协作与提交规则

本文件维护 LISA 的版本管理约定。当前由一人开发，产品规则以 [项目方案](PROJECT_PLAN.md) 为准，文档更新规则见 [README](../README.md#文档维护)。当前只有需求文档和独立原型，尚无正式应用构建、测试或 CI 流程。

## 分支与同步

- 主分支使用 `main`，保存可继续开发的完整状态；不额外建立长期 `develop` 分支。
- 日常开发和文档维护可以直接提交到 `main`。较大改动或实验按需使用短期分支，例如 `feat/qq-adapter`、`fix/task-pause`。
- 开始工作前检查 `git status`。需要同步时先运行 `git fetch origin`；远端已有 `main` 后，在干净的本地 `main` 上执行 `git pull --ff-only`，再创建任务分支。同步失败时先检查分歧，不强行覆盖。
- 单人开发不强制 PR；任务分支检查通过后合入 `main`，删除已完成的分支。以后有多人协作时再引入必要的评审流程。
- 不对共享的 `main` 强制推送，不重写他人已经使用的提交。已推送的错误优先通过新提交修复，必要时用 `git revert` 撤销。
- 本地提交与远端推送是两个动作；自动化助手按用户授权范围执行，不把每次编辑都理解为需要提交或发布。

## 提交信息与粒度

格式为 `type(scope): 简明说明`，`scope` 可省略。类型和范围使用英文，说明推荐中文，直接描述最终变化。

| 类型 | 用途 | 示例 |
| --- | --- | --- |
| `feat` | 新增功能 | `feat(chat): 接入 QQ 私聊事件` |
| `fix` | 修复问题 | `fix(tasks): 阻止暂停后启动自主任务` |
| `docs` | 需求、设计或使用说明 | `docs(plan): 明确主动联系边界` |
| `refactor` | 不改变行为的代码整理 | `refactor(memory): 统一检索范围过滤` |
| `test` | 新增或修正测试 | `test(tasks): 覆盖暂停边界场景` |
| `chore` | 仓库、工具或依赖维护 | `chore(repo): 初始化版本管理与项目基线` |
| `build` / `ci` | 构建或持续集成配置 | `build(web): 配置前端构建` |
| `perf` | 性能改进 | `perf(memory): 减少重复查询` |
| `style` | 仅格式变化 | `style(api): 统一 Python 格式` |
| `revert` | 撤销已有提交 | `revert: 撤销错误的任务调度改动` |

- 一次提交围绕一个可说明、可回退的目的；不混入无关重命名、全仓格式化或其他任务的改动。
- 同一需求的实现、必要测试与说明可以一起提交。确认产品决策时，项目方案、对应决策状态及变更记录在同一次提交中同步。
- 标题避免“更新”“修复一些问题”等模糊描述。复杂改动在正文说明原因、行为变化、实际验证及尚存限制。
- 未来出现不兼容的接口、配置或数据格式变更时，在标题类型后加 `!`，并在正文用 `BREAKING CHANGE:` 说明影响与迁移方法；数据库迁移文件随对应实现提交。
- 不提交临时调试输出、未解释的失败状态或声称未执行的测试已经通过。视觉功能变化使用 `feat` 或 `fix`，不因涉及 CSS 就一律使用 `style`。

## 跟踪与忽略边界

提交需求文档、本提交规则、原型及其素材、正式源码、数据库迁移、脱敏测试样例、通用人格与角色 prompt、部署模板，以及所选包管理器的依赖锁文件。锁文件与依赖清单同步更新；不为尚未选用的包管理器创建锁文件。

开发助手使用的 `AGENTS.md`、`AGENTS.override.md`、根目录 `.codex/`、`.agents/` 及个人编辑器配置仅在本地保留，不纳入版本管理。它们与应用使用的通用角色 prompt 分开；仓库文档不依赖这些本地文件才能阅读或使用。

[.gitignore](../.gitignore) 排除本地环境配置、凭据、运行数据、依赖、缓存、构建产物和测试报告。项目根目录的 `data/`、`runtime/`、`storage/`、`pgdata/`、`volumes/`、`backups/`、`exports/`、`indexes/`、`logs/` 预留给本地运行数据；部署时也可存放在仓库外。这些约定不要求现在创建目录或决定正式源码结构。

用户聊天、作品、个人演化 prompt、记忆、QQ 会话凭据、模型请求记录和数据库备份不进入 Git。通用模板、演示作品和合成测试数据放在明确的源码或示例位置，避免混入运行数据目录。新增数据输出位置时同步检查忽略规则；不以忽略所有 JSON、SQL、Markdown 或锁文件的方式隐藏源码。

允许提交 `.env.example`、`.env.sample` 及对应分环境模板，但内容只能是说明和占位值，不得带真实密钥、账号或私人数据。个人编辑器配置默认忽略；团队确需共享时，单独审查具体文件并调整白名单。

[.gitattributes](../.gitattributes) 统一文本为 LF，Windows `.bat`、`.cmd` 使用 CRLF，二进制素材保持原样。文本文件使用 UTF-8；PowerShell 读取文档显式指定 `-Encoding UTF8`。规则通过仓库文件生效，不要求修改个人全局 Git 配置。

忽略规则不会自动移除已经跟踪的文件。发现敏感内容被提交时，先撤销或轮换凭据，再按影响范围清理版本记录；不要只添加忽略规则后继续推送。

## 提交前检查

1. 用 `git status --short` 与 `git diff` 核对本次范围，保留其他任务的未提交改动。
2. 在项目根目录逐个路径暂存，例如 `git add README.md docs/CONTRIBUTING.md`；检查 `git diff --cached --stat` 和 `git diff --cached`，确认没有私人数据或生成物。
3. 执行 `git diff --cached --check`，修正意外的空白问题。
4. 文档改动检查本地链接、表格、状态及文档一致性。原型交互变化按前端规范做浏览器验收；正式应用建立后再运行与改动相关的真实构建与测试命令。当前不虚构测试命令或通过结果。
5. 使用约定格式提交；推送前复核目标远端、分支和待推送提交。

目前采用人工检查，不引入提交钩子、提交信息校验依赖或空 CI。后续有实际应用命令时再补充自动检查。GitHub 分支保护属于远端设置，不因添加本文件而自动启用。

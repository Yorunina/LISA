# LISA 前端美术与界面规范

版本：1.0。确认日期：2026 年 10 月 23 日。状态：当前视觉方向已确认，作为后续前端开发与视觉验收基线。

确认依据：用户认可当前原型，并要求“把现在的美术设计保存到文档中，后续实际开发时会按照文档标准进行开发”。决策记录为 [D11](PENDING_DECISIONS.md#d11-前端美术与界面基线)。

本文件维护视觉与界面规范；产品行为仍以 [项目方案](PROJECT_PLAN.md) 为准。可运行的视觉参照是 [前端原型](prototype/index.html)，具体样式来源为 [styles.css](prototype/styles.css)，交互示例来源为 [app.js](prototype/app.js)。原型使用虚构数据，无需安装依赖即可用浏览器打开。

## 1. 适用范围与执行方式

- **已确认设计**：私人书房风格、现有配色与字体分工、以阅读为中心的布局、三个主区域、书封与便笺等视觉语言。后续页面沿用此基线，不自行换成另一套主题。
- **原型参数基线**：以下尺寸、颜色和动效数值从现有原型提取，供实现时直接使用。它们不是用户逐项审议过的独立产品决定；允许为真实内容、字体差异及可读性作局部调整，并记录有意改变。
- **开发补齐要求**：原型未完整覆盖的加载、空白、失败、冲突、键盘与窄屏操作，按本文件的呈现原则补齐；具体业务触发条件引用项目方案及相应决策条目。

正文编辑、分支比较、角色 prompt、检索配置和记忆管理必须保留。采用什么框架、编辑器或组件库由后续技术设计决定；组件库默认外观应适配本规范。

出现差异时，产品行为按项目方案执行，视觉按本文件执行。原型是可视参照，不以原型中的简化功能、遗漏状态或示例文案覆盖现行需求。后续调整先同步相应规范与原型，保留有价值的历史评审。

## 2. 美术方向：私人书房

核心感受是安静、温暖、克制、有文学感。用户进入的是自己与 LISA 共同维护的书房，作品是页面中心，LISA 的存在通过便笺、作者署名与具体进展体现。

| 视觉要素 | 使用标准 |
| --- | --- |
| 页面底色 | 暖纸色铺底；正文纸面略亮，与背景形成柔和层次 |
| 主色 | 墨绿用于品牌、主要操作、当前选中项与关键文字 |
| 辅助色 | 鼠尾草绿用于轻量选中、状态与资料标签；陶土色用于需要留意的差异及提醒 |
| 排版 | 标题、文学正文使用衬线字体；导航、操作、表单和状态使用无衬线字体 |
| 留白 | 通过区域间距和细分隔线组织内容，正文保留宽松行距 |
| 表面与装饰 | 扁平纸面、细边框、小圆角、低强度阴影；装饰集中在书封、便笺和少量星花符号 |
| 图像 | 书封可以使用简洁几何图形。示例拱窗、山丘、太阳体现书籍装帧感，可随真实作品更换 |

新增页面避免大面积高饱和渐变、霓虹发光、厚重玻璃效果、装饰性数据图表及大量浮动卡片。不要用角色立绘、亲密度仪表或 Agent 编排画布替代现有书房布局。日期、英文眉题和装饰符号不得抢占正文的注意力。

## 4. 字体与排版

### 字体分工

原型字体栈如下，按可用字体回退；首选字体未安装时，仍应维持中文宋体的文学质感与工具文字的清晰度。

```css
--serif: "Noto Serif SC", "Source Han Serif SC", "Songti SC", "SimSun", serif;
--sans: "Microsoft YaHei", "PingFang SC", system-ui, sans-serif;
```

原型没有下载字体。后续若引入字体文件，需在技术实施时明确来源、使用许可、加载与回退策略；不把外部字体服务作为页面可用前提。

### 字号基线

| 元素 | 桌面原型 | 手机原型 | 用法 |
| --- | --- | --- | --- |
| 全局工具文字 | 14px，行高 1.6 | 同左 | 无衬线基线 |
| 页面主标题 | 32px，行高 1.5，字距 2px | 26px，字距 1px | 衬线，单页一个主要标题 |
| 作品名 | 26px，字距 2px | 22px，字距 1px | 书封旁的内容标题 |
| 正文章节标题 | 23px，字距 3px | 21px | 衬线居中 |
| 文学正文 | 15px，行高 2.2；宽屏 17px | 15px，行高 2.1 | 深灰绿，段间距 17px |
| 便笺正文 | 15px，宽屏 17px | 14px | 衬线，接近手边阅读纸条的节奏 |
| 记忆内容 | 17px，行高 1.9 | 16px | 内容优先于元信息 |
| 主要按钮、表单标签、页签 | 12px 左右 | 按空间调整 | 无衬线，保持一致层级 |
| 英文眉题 | 10px，字距 2.5px | 9px，字距 2px | 非必要装饰信息 |

原型中部分来源、时间、标签和页脚为 9–11px，仅作为轻量原型的层级参照。正式开发时，用户需要阅读或操作的信息建议从 12–14px 起调试，触屏与表单适当增大。不能将 9px 元信息视为强制上线标准，也不能通过缩小字体处理长文本溢出。

正文首段不缩进，其后段落默认首行缩进 `2em`；段落样式应服从实际作品类型，诗歌、对话和列表不机械套用。编辑模式与阅读模式保持接近的字号、行距与行宽，降低模式切换时的视觉跳动。

## 5. 页面结构与空间

### 主导航

| 主区域 | 内部结构 | 主要任务 |
| --- | --- | --- |
| 作品 | 正文 / 故事分支 / 版本记录 | 阅读、编辑、重写、比较、恢复、导出 |
| 设定与角色 | 世界与约定 / 角色与 prompt / 检索配置 | 维护作品依据及角色配置 |
| 记忆 | 搜索、类型筛选、记忆列表 | 查看来源、纠正、删除、限制用途 |

账号与联系偏好位于侧栏底部。任务状态嵌入作品侧栏及相关操作位置，不另设抢占入口的总控仪表盘。保留单项目语义，不在书房顶部添加多项目切换器。页面标题、作品名和面包屑需区分清楚。

### 桌面尺寸基线

| 区域 | 原型参数 |
| --- | --- |
| 侧栏 | 宽 218px，高度随视口；顶部固定在可见区域；内边距上 35px、左右 22px、下 20px |
| 顶栏 | 高 73px，左右内边距 44px，底部 1px 分隔线 |
| 内容容器 | 最大宽度 1540px，居中；上边距 36px、左右 44px |
| 作品概览 | 书封 134px + 弹性作品信息 + 230–315px 便笺，列间距 29px |
| 常规书封 | 134 × 186px；宽屏高度 202px；窄屏按断点缩小 |
| 正文与侧栏 | 弹性正文 + 235px 右侧资料栏，间距 24px |
| 正文纸面 | 1px 边框，4px 圆角；正文区域内边距约上 35px、左右 48px、下 33px |
| 正文工具栏 | 内边距 15px 23px，章节选择在左，编辑及专注阅读在右 |
| 双列面板 | 两列等宽，间距 24px；普通面板内边距 25px |
| 角色页 | 左侧 230px 角色列表 + 右侧配置面板，间距 24px |
| 专注阅读 | 隐藏侧栏、作品概览和资料栏，容器最大宽度 1050px，保留退出入口 |

常用间距为 8、12、16、20、24、28、36、44px，正文与作品概览可使用上述专门参数。页面之间复用间距层级，不为每个面板建立独立的密度规则。长正文的实际行宽需结合字体校验，避免宽屏下出现难以追读的过长行。

## 6. 页面与组件细则

### 作品

页面从上到下依次为标题与简介、书封与作品简介及便笺、作品页签、当前内容。原型的秋日日期属于轻量装饰；真实产品使用有效时间或省略，不固定为示例日期。

正文以纸面为中心，章节名居中，工具栏和版本信息在纸面边缘。右栏依次展示当前创作状态、章节目录与本章参考资料。引用项可进入相应设定或角色详情。专注阅读隐藏辅助区域后仍能清楚返回。

分支比较使用两张等权面板并列，标明共同分叉点、分支标题、当前主线或备选状态。当前主线用墨绿顶边及文字标签强调，正文差异用淡暖色标记；选主线的行为遵守 D05，不将视觉选择状态解释为已决定自治策略。版本列表突出修改者、时间和章节，详情可阅读全文，恢复结果与历史记录要区分。

### 设定与角色

世界设定与有效约定使用简洁文本面板。明确约束和偏好分别标注，不用同一种标签暗示它们有相同优先级。

角色列表以姓名、简洁字标和身份组织，配置面板提供稳定的标签与多行 prompt 编辑区。作者职责查看与角色 prompt 编辑明确区分。检索页显示资料范围、召回数量、文本预算、恢复默认及实际引用资料；角色和分支范围需可识别，字段单位必须明确。

### 记忆

搜索与类型筛选置于列表上方。每张记忆卡依次呈现类型及来源、记忆内容、创作用途开关与纠正／删除入口。明确事实、相处推测、虚拟生活通过文字标签区分，推测保留依据或待确认说明。

纠正使用带来源说明的编辑面板。删除操作说明实际作用范围；文案随 D10 的结论更新。筛选无结果时提供简短提示，保留修改搜索词与筛选条件的入口。

### 通用组件

| 组件 | 视觉与交互标准 |
| --- | --- |
| 主按钮 | 墨绿底、暖白字，4px 圆角；原型内边距 9px 17px；在当前操作区突出最主要的动作 |
| 次按钮 | 浅纸面、细边框、墨绿色文字；取消、恢复默认等动作保持次级 |
| 文字按钮 | 用于轻量跳转和资料查看；方向箭头辅助识别，不单独承担含义 |
| 删除按钮 | 陶土红文字与边框，文案指向具体对象，不与普通保存共用外观 |
| 页签 | 当前项为深色文字与底部 2px 墨绿线；非当前项弱化，数量使用轻边框小标签 |
| 表单 | 浅底、1px 细边框、3–4px 圆角；标签始终可见；帮助文字放在字段附近 |
| 便笺 | 浅黄绿纸面、少量装饰、LISA 字标与衬线内容；不模拟聊天输入框 |
| 图标 | 统一线性图标，常用 18px、描边 1.5px；工具栏可用 14–16px，无实心彩色图标混搭 |
| 对话框 | 最大宽度 630px，最大高度 85vh，8px 圆角、内边距 28px；窄屏留 16px 外边距 |
| 遮罩 | 深墨约 30% 透明度，轻微背景模糊；关闭按钮和键盘关闭路径明确 |
| 轻提示 | 深绿底浅字，靠近视口底部；用于保存成功等短反馈，原型约 3.2 秒后消失 |

常规表面使用 3–5px 小圆角，圆形主要用于头像或小图标操作。便笺的折角感与书封的微小投影属于特定装饰，不扩展为所有组件的默认形状。`LISA` 字标与拱形小写 `l.` 保留当前视觉特征；人物姓名字标不固定为示例人物。

## 7. 响应式规则

原型按以下断点逐级覆盖，单位为 CSS 像素。

| 视口宽度 | 布局规则 |
| --- | --- |
| ≥1600px | 保留内容最大宽度；正文 17px；正文内边距约 40px 70px，避免无限拉伸 |
| 1151–1599px | 标准桌面布局：218px 左栏、正文与 235px 资料栏并列 |
| 901–1150px | 左栏缩为 184px；内容左右 27px；资料栏缩为 200px；日期装饰隐藏 |
| 601–900px | 书封与作品信息同排，便笺独占下一行；正文与资料栏改上下结构；比较面板纵向排列；角色列表改横向可换行 |
| ≤600px | 左栏改顶部品牌及三个导航项；顶栏 48px；内容左右 20px；正文左右 22px；辅助资料纵向排布，表单、对话框及操作区可换行 |

手机端先保证正文、章节、编辑及主要导航可用。英文装饰、日期、重复说明可省略，长作品名与按钮文字正常换行。

**开发补齐要求**：原型手机端隐藏了侧栏底部账号入口及部分引用信息。正式产品需在顶部菜单或相关详情补回可达入口，不能把隐藏布局当成功能裁剪。触屏操作扩大可点击区域；禁止通过整页缩放把桌面排版塞入手机。

## 8. 动效、可用性与业务状态

### 轻量交互

原型的颜色与背景过渡为约 180ms，页面淡入及约 4px 位移为 250ms，轻提示淡入为 200ms。使用系统减少动态效果偏好时关闭非必要动画。动效用于解释状态切换，避免持续闪烁、漂浮和文字逐字展示干扰阅读。

键盘焦点使用清晰描边，原型为 2px 陶土色、外偏移 4px。导航、页签、按钮、表单均可用键盘操作，图标按钮有文字名称。对话框打开时管理焦点，关闭时返回触发位置；切换页面不把用户留在已隐藏控件中。输入中的正文与配置不得因普通导航静默丢失，具体保存机制由实现任务确定。

### 状态呈现

| 状态 | 呈现原则 | 行为依据 |
| --- | --- | --- |
| 进行中 | 在任务所在位置显示正在处理的对象及可用操作，保留已有正文；没有真实进度时不显示虚假百分比 | 项目方案的任务规则 |
| 完成 | 简短文字与轻量绿色状态标记；可查看记录；不持续打断阅读 | 采用与通知的细节按 D04 |
| 失败 | 清楚说明失败对象、已有内容是否受影响、可否重试或取消；重要错误不只出现于短暂提示 | 具体失败处理按任务设计 |
| 暂停 | 使用明确文字说明自主行为已暂停，手动操作与自动推进分别呈现 | D01 已允许网页单次重写，结束后仍暂停；完整暂停与恢复规则见现行决策 |
| 编辑未保存 / 保存中 / 已保存 | 在编辑区域持续可辨认，成功后可辅以轻提示；失败时保留输入 | 网页编辑优先、版本规则 |
| 版本冲突 | 明确标识当前有效版本和独立冲突草稿，不以普通成功样式掩盖冲突 | 项目方案的输入版本检查 |
| 尚无作品 / 无记忆 / 筛选为空 | 给出对应语境的简短说明，保留实际可用入口，不虚构进度 | D02 开写前共识及其他现行规则 |

## 9. 文案与示例边界

标题可以有文学感，例如“故事，慢慢发生。”；按钮、字段、错误和状态用直接具体的语言，例如“保存修改”“角色 prompt”“检索配置”。不把操作结果写成令人猜测的诗句。

LISA 便笺体现具体观察、创作想法与对话延续，避免通用夸赞和关系压力。演示中的《在雨停之前》、许知夏、沈舟、便笺、日期、章节数量和记忆均为虚构占位内容，不代表初始人格、实际用户经历或固定作品类型。日记项目沿用同一书房风格，内容名称按项目调整。

原型中的召回 6 条、文本预算 2400 字、完成状态与两条固定分支仅为演示。后续使用实际配置与数据。作品页不增加用户模型选择；不把技术调用链、服务拓扑等实现细节作为主要用户流程。

## 10. 后续开发验收

以下为开发完成后的检查要求，不代表正式功能当前已实现或已通过验收。

1. 对照原型检查作品、分支、设定与角色、检索、记忆页面；暖纸底、墨绿主色、衬线阅读与无衬线工具文字保持统一。
2. 检查常用桌面宽度、各断点前后和 390px 手机宽度；页面无意外横向滚动，长中文标题、长 prompt 和空列表均正常排版。

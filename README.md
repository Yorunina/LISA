# LISA

LISA（Literary Interactive Story Assistant）是一个以 QQ 私聊为主要入口的交互式文学创作伙伴。每位用户拥有独立发展的 LISA；LISA 以朋友关系开始交流，自主维护一个文学创作项目，并通过网页工作台向用户开放正文、版本、设定和记忆的管理能力。首版只有一条作品内容线，不提供创作分叉。

当前处于需求与架构设计阶段，尚未实现正式应用。“私人书房”前端美术及整体架构与工具栈已于 2026 年 10 月 23 日确认；独立交互原型作为视觉参照，不构成额外业务规则。产品基线建立于 2026 年 10 月 22 日。Git 管理约定见 [贡献指南](docs/CONTRIBUTING.md)。

首版采用 React / TypeScript / Vite 与 Tiptap 工作台，Python / FastAPI 后端，PostgreSQL / pgvector 统一存储，Procrastinate 后台任务及 Docker Compose 部署。面向最多千人，以单体、有限并发与排队起步；完整职责见项目方案“技术架构与工具栈”（D12）。改稿后的语义一致性由用户维护，生成期间编辑只提示，保留普通版本记录与恢复。

## 前端设计原型

用浏览器直接打开 `docs/prototype/index.html` 即可，无需安装依赖。采用暖纸色、墨绿、宋体正文与书封元素，围绕作品阅读组织页面。该美术方向已确认（D11），后续实际开发按 [前端美术与界面规范](docs/FRONTEND_DESIGN.md) 执行。点击左下角“关于这间书房”或顶部信息图标，可查看配色、字体、设计意图与原型边界。

可以体验正文编辑保存、章节切换、专注阅读、版本恢复、世界设定编辑、角色 prompt 编辑、检索配置、记忆搜索／纠正／用途开关，以及示例正文导出。原型仍含旧版的结局比较、主线标记与分叉说明，这些已被 D05 的首版裁剪取代，仅作为历史演示保留，正式工作台不实现。AI 重写和 QQ 绑定没有接入服务。全部示例数据仅存于页面内存，刷新后重置；请勿用于保存真实创作。

需要 HTTP 预览时，在项目根目录运行 `python -m http.server 8765 --bind 127.0.0.1 --directory docs/prototype`，然后访问 `http://127.0.0.1:8765`。原型源码为 HTML、CSS、JavaScript；这不决定正式应用框架。示例人物、作品和便笺不构成 LISA 初始人格的确认，D01 至 D10 的状态按现行待决策清单处理，不受本次美术确认改变。

## 文档维护

- 当前产品规则以项目方案为准，其中“建议默认值”和“实现建议”不等于用户已确认。待决策清单只管理问题、候选答案和决策状态，不另写一份完整产品方案。
- 决策确认后，在同一次文档更新中修改项目方案、待决策条目的结论与日期，并更新项目方案的简短变更记录。
- 设计评审保留评审当时的判断，不作为另一份现行规范。后续结论变化通过项目方案与决策记录追溯。
- 确实被替代的完整文档才移入 `docs/archive/` 并修正链接；当前没有需要归档的文件，不创建空归档目录。
- 技术方案、示例对话及其他专题达到需要独立维护的规模时再建文件。当前不创建空技术方案、代码目录或逐次聊天记录。

## 源文件与运行数据

后续通用人格模板及作者、角色的基础 prompt 属于可版本化源文件。各用户演化出的 prompt、聊天、作品、记忆、索引、日志和备份属于运行数据，应独立存储；密钥通过本地或部署配置提供，不提交到源码仓库。

仓库地址为 `https://github.com/Yorunina/LISA.git`，主分支约定为 `main`，远端名称为 `origin`。单人开发以 `main` 为主，较大改动按需开短期分支，提交格式为 `type(scope): 说明`；完整约定见 [Git 协作与提交规则](docs/CONTRIBUTING.md)。[.gitignore](.gitignore) 排除本地开发助手配置、私人运行数据、凭据、依赖及生成物，[.gitattributes](.gitattributes) 统一跨平台换行。通用 prompt、脱敏样例及实际选用的依赖锁文件应纳入版本管理。

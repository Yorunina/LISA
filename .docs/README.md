已完成任务规格、启动包、逐轮测试/排障和环境重载记录已移至 [.docs/archive/](archive/README.md)。**默认不读取归档、完整实施历史、决策历史或评审**；仅需要追溯某一任务时先检索其 ID / 标题，再按段读取。现行产品方案、接口边界和未完成任务继续留在活跃文档。

## 新任务从这里开始

需求接入默认只读本页与 [待决策清单](PENDING_DECISIONS.md)，随后按下面的主题读取项目方案对应章节及其关联规则。不要默认加载整个文档目录、完整方案、决策历史或评审。首次全面评审、跨模块设计时再扩大阅读范围。

用户当前明确决定优先于旧文档；先识别具体差异，再同步现行规则。需求讨论不自动扩展为编码；实现以本轮明确授权为准。已确认决定不重复询问，“建议默认值”“实现建议”不等于用户确认。

具体开发任务接入时，继续读取 [开发接入步骤](DEVELOPMENT_TASKS.md#开发-agent-接入步骤)，按本轮目标选择任务 ID、依赖与未完成验收，再加载相关产品正文。模块职责与当前状态统一维护在该文件；已完成能力不重复搭建，任务顺序不自动授权执行后续批次。

## 文档维护

1. 每轮聚焦少量相关决定；用户确认后，同步项目方案对应正文、决策记录的状态与结论及确认日期和依据、待决清单的剩余问题、[变更记录](CHANGELOG.md)。只有导航、阶段或专题职责改变时才更新本页，不再逐轮复制产品结论。
2. 决策编号稳定；仅部分回答时保留剩余问题，待确认内容不得标成已确认。结论反转时记录被替代内容与新依据，不删除历史。新增编号前检查决策索引。
3. 不为每轮聊天新建文档，不维护第二套完整方案。专题确需独立维护时再拆分并更新导航；示例模板、通用 prompt 可以版本化。
4. 已完成任务的详细规格、逐轮实施/测试/排障和旧交接按批次归入 `.docs/archive/`，活跃页保留完成 ID、简述与证据链接；部分完成保留剩余范围及真实验收，不把整批提前完成。归档标明日期及现行入口，修正相对路径/锚点，默认按需读取。仍有效的产品规则、接口边界、运行方法与待办不因实现完成而归档；评审不因日期较早就删除。决策和变更记录继续维护。
5. 项目文档和原型统一存放 `.docs/`。根 `AGENTS.md` 仅保留工具自动发现所需的本地加载指针，不复制规范；Git、依赖和运行配置留在工具要求的位置。个人运行数据、凭据、索引及日志与源文件分离，详见 Git 协作规则。
6. 文档用 UTF-8，检查本地链接及锚点、表格、状态和跨文件一致性。正式应用构建及业务测试按实施记录逐批核实，环境探针不能代替功能验收。整体技术方向按方案，具体已安装版本与验证边界查开发环境及锁文件。
7. 开发任务按 [接续规则](DEVELOPMENT_TASKS.md#完成条件与实施记录) 更新最新状态与实际验证；完成细节追加既有批次归档，不为每次聊天新建文档或让活跃页持续堆积历史。产品调整时检查任务及验收映射；当前运行方法维护在开发环境，历史证据移入归档，不重复维护产品决策状态。

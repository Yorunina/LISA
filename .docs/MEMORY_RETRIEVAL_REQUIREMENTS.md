# LISA 对话连续性与分层记忆改进需求

更新：2026 年 10 月 29 日。状态：第一阶段代码与相关隔离验证完成，真实向量小样本已记录；正式加载、回答语义、QQ与多日效果待验。用户已授权派子代理实施，要求避免过度设计或过度防御，低可行性或高成本项先咨询；范围为 MR01—MR03 及 MR06，第二、三阶段仍按下文接续。产品规则以 [项目方案](PROJECT_PLAN.md#长期记忆与检索) 为准；既有工程及本专题接续归属 [B14](DEVELOPMENT_TASKS.md#b14-记忆读取可靠性优化方案) 与 [B17](DEVELOPMENT_TASKS.md#b17-短期对话连续性与图片委托补全)，效果指标沿用 [B16 评测口径](OPERATIONS_DASHBOARD_REQUIREMENTS.md#rag-固定评测)。

日常短消息应能持续承接前文，稳定的用户资料应可靠提供，事件记忆应按当前问题选择。首批建议调整短期窗口、改善检索查询与候选选择；用户核心资料列为第二阶段设计，混合召回按评测结果接续。每个阶段独立验证，不以引入更多层次作为完成标准。

## 用户要求与当前基线

用户明确要求参考 QQ LLM 软件及插件；日常消息多为约 10—30 字，因此大幅提高最大逻辑轮数，正文容量维持接近现值，每轮最长保留 1 天。此前助手提出的 24000 字节扩容不采用。

已有真实语料抽取的测试样本支持短消息使用方式：确认集 24 条输入中 21 条不超过 30 字，中位数 10.5 字；开发集 12 条均不超过 30 字，中位数 9 字。统计来自本机忽略目录 `runtime/reports/real-chat-gold-v1/{confirm,develop}.json`，不复制私人原文。选取样本不能代表全部线上分布，也不能替代对 LISA 生成回复、合批消息及分条总长度的检查。

| 路径 | 实施前基线 | 本专题需要解决的问题 |
| --- | --- | --- |
| 短期对话 | 6 个逻辑轮次、6000 UTF-8 正文字节、整轮最多 30 分钟，三个上限共同生效 | 短句尚未用满容量就受轮数限制，较长间隔后无法接续 |
| 查询 | 本轮合批消息或图片理解文字，取末尾最多 1500 字符生成查询向量 | 省略表达可能缺少人物、地点及对象线索 |
| 个人语义候选 | 按余弦距离取 5 个切片，再读取当前记忆全文并去重 | 同一记忆多个切片占据候选位置，减少不同记忆数量 |
| 个人资料装入 | 默认最多 5 项、1500 字符，包含依据、元信息及格式；长记忆整条省略 | 命中候选不代表最终进入模型，不能单看检索数量 |
| 近期兜底 | 私有结果为空时，按更新时间读取当前可用记忆，最多 1200 字符 | 按时间兜底不等于语义命中，不能用于证明召回率 |
| 稳定用户资料 | 普通记忆中的事实与偏好仍依赖召回；LISA 人格和风格卡另行提供 | 缺少少量用户核心资料的固定读取路径 |

基线代码入口：[chat_context.py](../lisa/chat_context.py)、[chat.py](../lisa/chat.py)、[recall.py](../lisa/recall.py)、[retrieval.py](../lisa/retrieval.py)、[memory.py](../lisa/memory.py)。

## 目标与分层职责

| 内容层 | 读取方式 | 允许承担的职责 |
| --- | --- | --- |
| LISA 人格与现有约束 | 沿用当前固定输入 | 身份、交流方式及任务边界；不等同于用户事实 |
| 短期对话 | 读取尚未过期且装得下的完整轮次 | 理解指代、补充、改口和未完成委托；不自动产生长期事实 |
| 用户核心资料 | 第二阶段建议固定读取少量指定记忆 | 明确确认且长期稳定的称呼、事实或交流偏好 |
| 动态长期记忆 | 检索当前有效条目 | 经历、事件及相关偏好，保留事实、推测、虚构和生活类型 |

这些是逻辑读取层，不要求分别部署服务、数据库或索引。未形成长期条目的信息在短期窗口过期后无法找回；验收应将记忆形成失败与检索失败分开。

## 首批需求

已授权首批包含 MR01—MR03 及对应评测；先比较各项独立效果，再验证组合。下列参数作为首轮工程起点，不增加产品审批事项。

### MR01 扩大短期轮数与保留时间

| 参数 | 实施前 | 首批工程值 | 性质 |
| --- | --- | --- | --- |
| 最大逻辑轮数 | 6 | 50 | 首批采用的工程起点，可按样本调整 |
| 正文容量 | 6000 字节 | 6000 字节 | 维持现值，不预先大幅扩容 |
| 整轮最长保留 | 30 分钟 | 24 小时 | 用户要求；滚动时长，不是每日零点清空 |

1. 一轮包含一次成功采用的合批用户输入及对应已确认送达的回复；分条不额外占轮数，正文容量统计双方内容总和。
2. 整轮按最早用户输入接收时间计算到期；追加回复、后续聊天或重启不延寿。到期即读不到，沿用既有清理设施删除。
3. 时间、轮数和字节任一上限触发时，移除最旧完整轮次，保持连续的近期窗口；不跳过较长的新轮次去拼更旧片段。单轮超过容量时不截断保留。
4. 保存容量与实际请求容量分别约束。消息时间、来源标识、人格及输出结构均计入完整请求预算；即使正文未满，也允许请求前整轮裁剪。当前输入保持完整。
5. 仍只读取本账号及当前 QQ 绑定的窗口。记忆纠正或删除、绑定更换及账号删除沿用清理与在途复查，失败、取消和未知发送不能成为已告知内容。
6. 24 小时内的临时状态必须按发生时间理解。上午准备出门不证明晚上仍在路上，昨日计划不证明今日已完成；已受理或已取消的图片委托不因窗口延长再次执行。

### MR02 改善短句的查询线索

1. 当前用户消息始终优先；查询总长度沿用最多 1500 字符，不增加一次独立查询改写或分类模型调用。当前文本超过预算时沿用当前限长方式，不为历史挤掉本轮内容。
2. 对明确的指代或承接表达，允许用剩余空间补最近的相关自然语言消息。建议最多取 2 条、历史合计最多 400 字符，标注说话人与消息时间；给尚未处理的消息分配预算，避免单条长回复挤掉用户的指代对象。不是 2 个全天轮次摘要。
3. 无法可靠判断关联时优先只用本轮。明确转题、改口和撤销以当前意思为准；不能因为本轮很短，就把旧主题自动作为当前检索目标。实现优先采用少量可测规则，不建设话题识别系统。
4. 历史助手内容只提供指代线索，不成为用户事实、操作授权或长期记忆写入证据；本轮候选写入校验继续只接受当前轮依据。
5. 只读取 MR01 允许的现有窗口，不读 QQ 历史、不回填过期内容、不保存查询正文副本。图片文字仍按现有处理路径使用，图片观察不冒充用户声明。
6. 明确转题和无关前文是同等重要的验收组。若前文扩展没有改善目标题或持续增加误召回，应缩小或关闭扩展，保留其他改进。

### MR03 扩大候选并按记忆去重

1. 首批作用于普通聊天的个人长期记忆路径。作者世界书、章节、角色知识及公共表情的候选数、预算和顺序保持现有规则，避免通用函数修改造成隐式扩展。
2. 将候选切片数与最终记忆条数分开。工程起点为最多 15 个语义切片候选，按当前记忆 ID 去重后选最多 5 条，仍按原相似度顺序，稳定处理同分。
3. 每条记忆以最优命中切片取得排序位置，不因切片多而重复加分。有限候选不足 5 条不同记忆时允许少于 5 条，不循环扩搜补满，也不新增 embedding 调用。
4. 对去重后的有界候选依次尝试装入，某条太长时继续尝试后面的候选，直到达到最终条数或耗尽候选。仍使用当前全文、依据和元信息，整条省略，不摘要、不改写、不截断个人记忆。
5. 首批保留个人检索资料 1500 字符及完整请求预算。MR03 不以增大注入量代替候选质量；相似度阈值、语义去重和付费重排不在首批加入。
6. 查询及装入时复查账号、用途、作品范围、有效修订与当前向量空间。近期兜底条件、公共表情追加顺序、确定失败降级和 unknown 停止规则继续沿用 B14；减少或丢弃的资料不记录成最终注入。

## 第二阶段 核心资料固定读取

MR04 为待确认设计，不阻塞首批。推荐在现有记忆上提供用户可见的核心标记，复用原条目的内容、修订、权限及删除路径；不另存一份自动总结的用户档案。

1. 首版仅由用户在现有记忆编辑入口明确设置或取消。聊天 Agent 继续按原规则形成普通记忆，不自动把高频、相似或多次召回的条目标为核心。
2. 核心资料用于普通聊天；默认沿用账号级共享记忆，允许类型建议先限事实和偏好。推测、文学想象、短暂状态、未来计划及 LISA 自己的虚拟生活不自动进入用户核心资料。
3. 固定读取也检查 `active`、`allow_chat`、当前修订及所属账号；不绕过写作用途权限，不自动提供给作者或角色。核心标记只改变读取优先级，不提升真实性。
4. 核心与动态结果按同一记忆 ID 去重，动态候选排除已装入核心项。建议最多 3 条、核心最多 600 字符，与动态个人资料共用 1500 字符总预算；参数均为待验证起点。核心必须完整装入才算使用，不默默截断。
5. 核心资料过长或超数量时，在保存或标记操作中明确提示，允许保留为普通记忆；用户不应依赖不可见的随机省略。当前输入、人格及必要约束仍服从完整请求预算，超限时沿用既有处理，不强行生成。
6. 编辑、取消核心、禁用用途及删除在后续读取中立即生效；生成中修改继续使用既有修订失效机制。旧条目默认非核心，迁移不得自动选择个人事实。

实施前只需确定核心选择权及共享预算策略两项产品取舍；API、字段和页面布局在开发阶段按现有记忆编辑结构细化，页面修改遵循 [前端规范](FRONTEND_DESIGN.md)。

## 第三阶段 混合召回候选

MR05 在真实语义样本证实人名、地名、作品名或专有词漏召回后再评估。建议在相同账号、作品、用途及修订过滤内，合并文字精确命中与向量候选，按记忆 ID 去重，再在固定最终条数和字符预算内选择。

中文分词方式、融合排序、时间加权、近重复抑制及重排模型不预先建设。普通旧经历不应仅因年代久远而被统一淘汰，临时状态也不能因新近而挤占稳定事实。启用混合方式前需与向量单路做同题对照。

以下消息为合成示例。工程检查可使用隔离数据库和替身；语义检查需使用实际 embedding，回答行为需使用实际聊天模型。相同场景不得把前一类通过写成后一类通过。

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| A01 | 30 个双方均为短句且总字节不足 6000 的成功轮次 | 不再因第 6 轮上限丢失前文，指代来源可见 |
| A02 | 超过 50 轮或合计超过 6000 字节，含合批及分条 | 达到任一上限按完整旧轮次淘汰，保持近期连续性；双方正文均计量 |
| A03 | 同一轮接收后 23 小时 59 分与满 24 小时读取 | 前者在其他预算允许时可读，后者不可读；追加回复或重启不延寿 |
| A04 | 正文装得下，但时间和来源包装后请求超限 | 按完整旧轮次裁剪，当前输入和必要约束不截断 |
| A05 | 近期明确谈某地，本轮“那里我还挺想去的” | 查询扩展包含必要指代线索，能够找到预先标注的相关记忆 |
| A06 | 近期谈旅游，本轮转问“这个报错怎么处理”或明确换话题 | 查询不被旧旅游话题主导，回复不强行引入旧经历 |
| A07 | 一条记忆多个切片占据原前 5，另一相关记忆排第 6—15 | 去重后后者有机会进入最终结果，同一记忆只计一次 |
| A08 | 前排完整记忆过长，后面有可装入的相关短记忆 | 长条省略，继续尝试后续有界候选；不新增查询或裁掉否定、条件、依据 |
| A09 | 多个语义候选均无关，或向量不可用而走近期兜底 | 分别记录相关性不足与兜底，不把非空结果当召回正确；确定失败及 unknown 沿用现有边界 |
| A10 | 早晨说“准备出门”，晚间询问；旧图片已受理或已取消 | 不把旧状态断言为当前状态，不重复创建旧委托 |
| A11 | 其他账号、非当前作品的长期记忆、禁止用途、删除或修订失效 | 长期资料遵守账号/作品/用途过滤；短期补充只读本账号当前绑定的有效窗口；禁止或已清除内容不进入请求，修订中止沿用现有机制 |
| A12 | 核心资料与当前话题不相似，随后编辑、取消或删除 | 第二阶段：有效核心仍固定提供；变更后旧内容不再使用，动态结果不重复注入 |
| A13 | 用户未指定核心；助手猜测偏好或临时状态 | 第二阶段：不擅自标记核心，不从历史重新提升事实 |
| A14 | 同义描述与专有名字分别提问 | 第三阶段：比较混合与向量单路的命中、误召回及最终覆盖，权限过滤一致 |

## 效果评测与交付判断

MR06 复用 B16 指标和报告结构。保留现有 40 题确定性链路基准作为回归；其中向量由合成规则生成，不能作为真实语义召回率。新增一组约 20—30 个同题可复跑的轻量场景，覆盖指代、转题、专有词、重复切片、长条省略、无答案和时间变化，至少同时包含应召回与不应召回的问题。用户真实材料只在已允许范围内本地使用，Git 中保存合成或脱敏样例。

| 指标 | 判断内容 |
| --- | --- |
| 候选 Recall@K | 前 K 个去重候选命中了多少预先标注的目标记忆；对照固定 K=5，并另报有界候选池的目标覆盖，记录切片上限及最终条数 |
| 候选 Precision@K | 实际候选有多少相关；无答案和权限排除题单列 |
| 最终上下文覆盖 | 目标完整记忆有多少真正进入最终请求，预算省略不算成功 |
| 回答使用与连续性 | 人工核对是否正确承接、是否误用旧状态、是否编造或答非所问，单列于检索指标 |
| 资源消耗 | 请求实际输入量、embedding 与生成耗时、调用次数及费用；扩候选不增加模型调用 |

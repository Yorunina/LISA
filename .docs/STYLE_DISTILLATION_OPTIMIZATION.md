## 1. 本轮目标与取舍

2026 年 10 月 27 日用户另行要求建立 golden set，随后明确本次只评估聊天蒸馏机制是否减少 AI 感、促进自然交流，并选择先完成合成基准。独立于下述已完成开发范围，评测协议、固定数据和实测结果统一见 [聊天蒸馏合成基准](CHAT_DISTILLATION_BENCHMARK.md)；本轮不扩展写作或个人语料评测，也不因评测自动修改蒸馏机制。

交付一组能说明改进来自哪里的对照结果，以及支撑改进的最小代码调整。先修复可确认的链路问题，再根据少量代表材料检查归纳和编译损失，不预先建设完整性格体系或评测平台。

当前源码已显示两类具体风险：候选 prompt 在接受评测后才由结构化规律重新编译，实际使用文本可能不同；分批和最终小清单反复压缩，可能丢失人物与笔法的条件差异。它们是优先验证对象，不是已经证明的全部原因；真实用户当前应用版本和自然度仍须实际核对。

| 第一轮必须做 | 具体交付 |
| --- | --- |
| 统一使用与评测 | 评测使用最终编译并按场景/任务取用的卡片；隔离试用与正式生成共用必要的风格处理和表达约定，明确上下文差异 |
| 保留关键条件和辨识度 | 在现有发现与报告结构内，检查并修复归纳、合并、选择和字节裁剪造成的损失；只做有依据的局部调整 |
| 小样本聊天对照 | 少量典型情境，分别记录 AI 感与人物辨识度；需要时用短的两三轮转折检查稳定性 |
| 轻量作品验证 | 对白场景与叙述段落各一个新内容任务，检查笔法和条件是否保留；不宣称代表长篇质量 |

## 2. 工作顺序

### 2.1 核实并统一实际链路

先检查旧方案/候选的编译结果、当前场景或写作任务选择，以及试用和正式调用的差异。复用现有模块与接口，必要时提取一个小的共用函数，不新建生成编排层。

评测顺序改为“形成候选 → 编译和选择 → 生成对照 → 开发侧最多一次局部修订 → 冻结 → 留出检查”。评测不能继续只验证随后被替换掉的自由 prompt。手写编辑的卡片仍以用户输入为准，不能被旧报告覆盖；版本记录和应用引用不自动更新。已有结构化报告仍会使用修复后的共用编译器，其规则选择与渲染可能变化，应做兼容检查并在交付时说明。

网页试用可以缺少真实记忆、生活和作品上下文，但风格文本处理与通用表达约定应与正式调用一致。不能据单轮网页试用声称完整 QQ 链路一致，更不能为验证而发消息、保存记忆或修改作品。若本轮仅完成共用风格链路，验收明确这一范围。

2026 年 10 月 28 日共同底座接续：核心交流逻辑与个性层的现行分工及收缩范围见[交流与人格](PROJECT_PLAN.md#交流与人格)。正常聊天已具备组合入口；用户后续要求不增加不必要复核，首轮试聊沿用单次生成和一次调用许可，只复用轻量资源加载/选卡并对齐快照、隔离与清理，不接额外复核、不重构本专题全部蒸馏对照。已有 review 保留为本首轮之外的可选模式，不自动启用；单次和两步效果证据分开。不增加日常人格分类或人格改写调用，也不将多日人格证明作为首轮工程前置。旧评测使用的交流约定与新模式有差异时标明，不能直接沿用其效果结论。

### 2.2 只调整实际丢失的行为规律

使用现有的条件、回应/写作选择、反例、来源定位与限制字段；六维性格档案不作为新结构要求。检查代表性材料中的关键行为在各阶段是否还存在，并据此修改现有归纳提示、少量容量限制或编译规则。

优先保留“什么情况下做什么，什么时候不这样做”。稳定规律与局部表现分开，未观察到的场景保持未知；不能把来源人物身份、经历和关系迁入 LISA。假设性的目标颗粒度是“随口吐槽可以轻接，明确求助认真展开，审美分歧不为附和立即改口”，不把这套性格强加给所有人。

编译保留完整行为、必要条件和会改变行为的例外；重复证据说明放在报告中。不用不相关场景规则凑核心条数，不在字节边界留下半条指令。保留聊天 4000、写作 6000 UTF-8 字节上限，聊天核心最多 5 条、当前场景规则合计最多 2 条；不增加日常回复调用数。

通用表达约定只针对实际问题做小调整，重点检查自动安慰、无请求建议、心理补写、机械附和、追问和总结。自然度不靠统一短句、冷淡、粗口、错字或口头禅实现；明确求助仍应给足内容。

### 2.3 小规模对照后再决定扩展

聊天先覆盖普通分享、分歧、认真求助、玩笑转认真四类；拒绝展开/告别或误解修复可按材料补充。它们用于小样本检查，不建立固定 12 类场景库，不要求每次蒸馏全部执行。两三轮转折只在有必要时使用，调用必须纳入有限执行计划并记录消耗；按D09最新决定不受消费额度拦截。

比较旧版本和调整后的版本，固定模型、来话与其他上下文；允许平局和不确定。分开记录“更自然”和“更像目标人物”，不能用更短、更礼貌、更长或模型自评总分代替。若增加无蒸馏基线，明确它只用于诊断，不扩大为长期平台。

作品在相同题目、事实约束和近似篇幅下比较旧卡与新卡。对白检查回应方式、动作和潜台词；叙述段落检查视角距离、情绪细节和停顿。来源没有某种特征时不强行加入；长篇结构与四类任务全面验收留后续。

## 3. 验收与交付

| 项目 | 本轮验收依据 |
| --- | --- |
| 链路一致 | 测试证明评测使用最终编译和场景/任务选择结果；手写编辑与旧版本不会被无声覆盖；试用的上下文差异明确 |
| 规则保留 | 有辨识度的条件与例外在合并、选择和字节裁剪后仍有对应；不混入无关场景或半条规则，不迁移来源事实 |
| 聊天效果 | 少量旧/新对照，分别呈现自然度与人物辨识度；模型辅助观察和用户评价分别记录，不能宣称人工已通过 |
| 作品效果 | 对白与叙述各一个新内容检查；是否保留写法、是否有内容迁移分别说明，其他任务标未验 |
| 工程与代价 | 相关回归、字节上限、取消/清理和隔离无副作用不回退；记录实际调用与测试限制 |

先用合成、脱敏样例验证代码路径，再在有合适材料与可用环境时做有限真实模型对照。不得将替身输出写为真实模型效果；缺少代表性个人语料时，交付可用的试用/验证路径并明确个人效果待用户验收，不能借此阻止可完成的工程开发。

仅对关键行为、最终编译链路、完整规则裁剪、版本兼容和隔离边界补充必要测试，不建设独立评测平台。交付说明包括本轮具体改动、实际测试及对照范围、剩余不确定性；不提交用户语料或个人评测全文。

## 4. 沿用边界

- 复用现有上传、任务、report、版本、保存与明确应用机制，不改数据库结构，不新增复杂页面或自动切换方案。
- 沿用现有模型、4000/6000 字节卡片上限、有限调用计划及消耗统计；D09已取消文本消费额度；不增加分类模型或每轮去 AI 改写调用，不以扩大上下文替代修正。
- 保留原文终态清理、来源隔离、取消/迟到结果丢弃和账号删除；真实个人材料、原句与留出答案不进入长期报告或 Git。
- 正常聊天遵守 D24，仅用当前轮和合法独立记忆；本轮仅记录记忆缺失是否影响效果，不开发记忆/召回改造，不增加自动逐轮摘要或隐藏历史。
- 原文已清理后，旧卡不能恢复未保存的证据。需要重新来源分析时重新上传；已有结果仍可用于合成情境试用。
- 未获得提交、推送或服务重载指令，不在本轮擅自执行；开发和隔离测试不等于上线或真实 QQ 验收。

只有小样本对照显示现有结构仍是明确瓶颈，才提出对应后续改动、预期收益和代价。原创示范保存仍需单独确认。本轮结果没有明显改善时如实报告原因与限制，不自动扩大任务。

# 蒸馏质量优化方案

更新：2026 年 10 月 27 日。归属 D15 / B09；优先解决聊天 AI 感和性格扁平，同时覆盖作品蒸馏。

状态：用户认可优化方向，要求先整理具体方案，暂不改代码。本文件是专题设计提案，不表示以下字段、实验参数或开发任务已经逐项确认或授权实现。已确认产品边界仍以 [项目方案](PROJECT_PLAN.md#上传语料与风格蒸馏) 为准；工程状态见 [B09](DEVELOPMENT_TASKS.md#b09-风格蒸馏需求扩展)。

## 1. 目标与范围

第一优先级是让 LISA 根据来话作出合适且有个人差异的回应：普通分享不自动转成咨询，分歧时不机械附和，认真求助时能充分说明，多轮后仍保留立场与相处方式。第二优先级是让作品继承可执行的笔法、叙事选择和节奏，而不只得到形容词式画像。

本方案延续分层档案与受限运行时风格卡。增加分析深度和有效信息，先解决选择、压缩和应用中的损失，不直接扩大每轮上下文。

| 项目 | 本轮安排 |
| --- | --- |
| 已认可方向 | 深化分析档案、提炼条件化行为、改善实际聊天、深化叙事笔法、统一评测与正式应用 |
| 已确定优先级 | 聊天 AI 感与性格层次优先，作品蒸馏随后接续 |
| 当前交付 | 方案、阶段划分、验收方法及待定项；不改源码、提示词、数据库或已应用方案 |
| 继续沿用 | QQ TXT、作品 TXT/Markdown；目标窗口；原文终态清理；保存与应用分开；作品覆盖；版本和有限预算 |
| 暂不扩展 | 模型微调、新模型采购、额外风格分类模型、图谱、长期原文库、作品角色性格蒸馏、复杂编辑器 |

## 3. 聊天分析产物：行为、层次与证据

### 3.1 分维度分析，保留差异

| 维度 | 分析内容 | 运行时价值 |
| --- | --- | --- |
| 稳定取向 | 在多组材料中重复出现的关注重点、判断方式、审美取舍与回应边界 | 面对不同话题仍有稳定选择，而非只换语气 |
| 关系与场合 | 熟悉/不熟悉、群聊/私聊、轻松/认真场合下的可观察差异 | 保留亲疏和场合差异，不移植来源关系 |
| 接话行为 | 接受分享、具体追问、玩笑、异议、拒绝、结束、修复误解的条件 | 决定本轮做什么和何时停止 |
| 情绪回应 | 什么情况下轻接、认真回应、提供办法或暂不分析 | 避免每种情绪都走安慰与建议模板 |
| 表达分布 | 句式、措辞、消息组织、解释力度及其随场景的变化 | 保留自然变化，不变成每轮长度与口头禅配额 |
| 跨轮行为 | 被质疑后如何坚持或修正、话题如何延续、误会如何收束 | 验证互动过程，避免单轮像、多轮失真 |

每条规律建议记录：所属维度、适用条件、可执行选择、必要例外、支持的目标消息定位及独立组数量、冲突证据摘要、观察范围和不确定性。精确字段名、每维容量与输出额度在实施设计时确定。

稳定取向必须有跨组证据；局部表现只作为场景倾向，未观察到的维度保持未知。不诊断依恋类型或隐秘动机，不把幽默推断成外向，不把一次让步归纳为顺从。低频但有辨识度的规律可保留在档案，不能仅因罕见就提升为核心，也不能仅因罕见就删除。

跨批合并按相同条件去重，保留不同条件下的不同选择；冲突先检查场合、话题和对象是否不同。仍无法解释时保留冲突，不强行平均、不编造人格解释。不能将多份不同人物材料混为一个人，也不能把对不同人的表现直接移植为 LISA 与当前用户的关系。

### 3.2 目标产物的具体程度

以下为说明规则颗粒度的假设性概括，不是任何来源人物的观察或待应用人格：

> 日常吐槽时可用轻微玩笑接住；对方明确表达受伤或要求认真时收起玩笑，回应具体事情；对审美问题保留自己的判断，被指出事实错误时说明并修正，不能仅为顺着对方立即改口。

需要验证的是条件变化是否导致合理的行为变化；不要求每次逐字执行同一套顺序。档案可以描述这种层次，运行时只选择本轮相关部分。

## 4. 聊天生成：减少 AI 感并保留人格

### 4.1 根据本轮需要选择回应行为

将“分享、求助、讨论、宣泄、玩笑、试探、拒绝展开、告别”作为可同时存在的意图线索，不以一个关键词确定全部语义。显式要求和边界优先；不确定时使用核心规则，不自动补齐用户心理。

| 来话情境 | 期望行为 | 重点检查的问题 |
| --- | --- | --- |
| 普通分享、随口吐槽 | 回应一个具体内容，可简短停下 | 自动心理分析、无请求建议、每轮追问 |
| 明确求办法或解释 | 给足必要信息，表达仍符合人格 | 为追求口语或短句而不回答问题 |
| 玩笑与疲惫并存 | 结合上下文和明确要求决定轻重 | 看见“哈哈”就忽视疲惫，或看见“累”就套安慰 |
| 分歧、诱导附和 | 给出判断与理由，区分事实纠错和审美分歧 | 顺从改口、强行唱反调、通用两面话 |
| 不想展开、告别 | 尊重边界，允许自然结束 | 变相追问、布置选择题、制造续聊压力 |
| 对方指出误解 | 修正具体理解并承接话题 | 长篇道歉、自我说明、反复复述纠正内容 |

第一阶段不增加每条回复的模型调用，也不增加每轮独立“去 AI 改写”步骤。先整理现有指令职责，让通用表达约定只提供最低限度帮助，由有证据的人格行为决定语气、分寸和关注点。正常的解释、关心和结构化答复仍按用户需要保留，不以短、冷淡、粗口或错字代替自然度。

### 4.2 核心与场景卡的编译

- 保持聊天卡不超过 4000 UTF-8 字节，核心规则最多 5 条、本轮场景规则合计最多 2 条；混合意图不按标签数成倍增加规则。
- 全局核心来自真正跨场景的稳定规律，不用不相关场景规则凑满条数。冲突时按明确条件和证据范围选择；未知场景回退核心规则。
- 场景线索不等于用户意图已确认。第一阶段不增加分类模型；由有限条件包覆盖常见混合情境，具体无额外调用的选择方式通过对照确定。
- 运行时保留行动、适用条件和会改变行为的例外；支持数量、评审过程与重复的不确定性说明留在档案。不能为了省字节删除否定条件或把局部规律改成普遍要求。
- 按相关性、证据范围和辨识度选择完整规则。超限先删重复和低相关项，不把半条规则投入生成；仍无法满足预算时明确失败或退回可用核心。
- 具体人称、关系事实、现实身份、职业、兴趣事实和来源经历不得混入卡片。来源中的关系差异只转为条件化行为，不证明 LISA 已有该关系。

### 4.3 在 D24 内改善连续性

风格与记忆分开检查：对刚提出的话题答得生硬，可能是表达问题；不知道上次已达成的结论，可能是记忆或召回问题。评测应分别提供相同记忆、缺失记忆和经用户纠正的记忆，确认差异来自哪里。

连续性只使用已有合法的独立记忆与作品资料，必要记忆由用户填写或聊天 Agent 根据当前轮主动整理。可以检查明确约定、讨论结论、偏好和未解决事项是否得到适当承接，但不自动逐轮保存摘要、不建立隐藏聊天流水、不从已删除历史重建人格。无依据时承认信息不足；不虚构共同经历，不用陌生或亲密固定模板填补。

## 5. 作品蒸馏：从语言特点到叙事选择

沿用聊天侧的档案/卡片分离、条件化规律与证据范围，但采用独立写作分析维度，不把交流人格复制为作者风格，也不把角色观点当作者性格。

| 分析层 | 应保留的可执行差异 |
| --- | --- |
| 语言与段落 | 动词和修饰的使用、长短句转换、停顿与段落如何服务场景 |
| 视角与距离 | 信息局限于谁，何时贴近感受、转向外部观察或拉远概述 |
| 情绪与细节 | 直接命名情绪还是通过动作、物件、感官及注意力变化表现 |
| 对白与潜台词 | 回避、沉默、答非所问、话轮控制，以及动作怎样改变台词含义 |
| 场景组织 | 入场位置、信息揭示、冲突升级、转折、留白和离场方式 |
| 长篇节奏 | 场景与概述比例、铺垫回收、意象回返、章节收束与跨章推进 |

按作品、视角、场景功能和文体保留差异，区分跨作品稳定笔法与局部技巧。不按文件长度平均；不能用引号数量代替对白分析，也不能把章节数直接当语义场景数。体裁、视角和场景功能由实际分析说明判断依据，不确定时保留未知。

运行时写作卡继续不超过 6000 UTF-8 字节，按 scene/rewrite/diary/novel 选择任务包，再参考当前段落的功能与视角；用户要求、作品有效约束和人物知识边界优先。世界书与剧情来自当前作品，蒸馏只提供写法。

四类验证分别覆盖：全新场景、保持事实的改写、虚拟生活事实受限的日记、小说章节或跨段推进。没有某类适用材料时标为未覆盖；单个短场景不能支持整章或整部长篇结论。长篇验收另检查叙事距离、信息揭示和节奏是否持续，而不只看漂亮句子。

## 6. 评测设计与验收方式

### 6.1 先编译、再冻结、再检验

候选档案经过编译后，连同选择规则、通用表达约定和实际组装逻辑一起冻结。评测必须使用与正式调用相同版本的选择、字节预算和结构化输出；上下文仅使用隔离的合成资料或任务内临时语料，不发 QQ、不写关系记忆、生活事实、作品或后续任务。

验证摘要记录方法版本、配置、测试范围和适用限制；编译结果可用指纹核对，不记录含原文的请求副本。冻结后修改规则、手写卡片、编译器或组装逻辑时，原结果只能作为历史参考；需要重新检查受影响链路，不能沿用“已验证”结论。开发组最多一次局部修订，最终留出不参与修订。

网页单轮试用保留为快速预览，明确其不能代替正式链路隔离验证或真实 QQ 验收。手写人格、旧方案、缺少档案的版本继续可用；不静默重编译或改变用户已应用结果。

### 6.2 聊天验收集

建议准备 12 类情境：普通分享、轻微抱怨、明确求助、认真情绪表达、幽默、幽默与疲惫混合、审美分歧、事实纠错、拒绝展开、告别、误解修复、已有约定与话题承接。它们是测试库，不要求每次蒸馏全部执行；任务内仍最多选 6 个代表情境并先计算调用计划。

另设专门多轮实验，建议每组 4—6 轮，覆盖“玩笑转认真”“分歧到澄清”“误解到修复”和话题自然结束；比较当前已应用版本与新候选，固定其余上下文，并允许平局或不确定。诊断阶段可加入无蒸馏基线；预算不足时拆为独立、明确发起的实验，不自动额外付费运行。

多轮分两种：任务内临时历史实验用于检查行为连贯性；正式聊天链路实验按 D24 仅使用当前轮和合法独立记忆。前者通过不证明后者通过。由历史语料构造的后续来话可能依赖真实目标回复，须检查是否适用于候选；不适用时停止或标为脚本条件验证，不能当真实互动成功。

| 评价轴 | 判断内容 | 通过依据 |
| --- | --- | --- |
| 自然度 | 空泛复述、无请求建议、心理补写、模板开头、强行总结、追问压力与复读 | 人工逐例标记问题及严重程度，模型只辅助定位 |
| 人物辨识度 | 相同情境下是否有稳定且有证据的关注点、分歧方式和表达差异 | 盲评解释差异，不凭口头禅或形容词判断 |
| 层次与适应 | 条件变化时行为是否合理变化，未观察场景是否保守处理 | 成对情境与反例检查；不要求所有场景套同一模式 |
| 连续性 | 立场、修复、结论承接及记忆纠正后的行为 | 多轮实验与正式链路分别记录 |
| 事实与边界 | 无来源身份、私事、经历迁移，无越权或隐性历史留存 | 必须无新增违规；严重问题阻止进入应用建议 |
| 工程代价 | 卡片字节、实际调用、耗时和费用 | 受现有硬限制约束，新增代价有独立记录 |

建议先跑小型基线，确定问题频次后再冻结量化阈值；不虚设“真人相似率”或声称统计显著。候选进入应用建议前应由用户在盲评中确认主要 AI 感问题改善、人物辨识度未下降，并且事实边界与连续性没有严重回退；若自然度提升但人格变通用，应继续修订而非宣告通过。保存和明确应用仍为用户操作。

### 6.3 写作验收与分析消融

同一题目、事实约束和大致篇幅下，对照旧方案与新方案。分别评价语言、叙述距离、对白潜台词、场景推进、节奏与内容迁移；小说章节与日记不能相互替代。句长、标点和对白比例只作描述性线索，不作为质量或作者身份判据。

在预算内按顺序比较“现有版本”“统一正式链路后的版本”“增加分维度档案后的版本”，必要时再单独检查场景选择和通用指令调整。每次只改变一个主要因素，避免同时换模型、扩大上下文和改提示词后无法归因。所有结果区分合成检查、真实语料留出、模型辅助评审、用户盲评和真实 QQ 多日体验。

## 8. 预算、兼容和清理

- 沿用每日 10 元共享余额；蒸馏无独立单任务金额上限，但有调用、输入和输出硬限制。常规聊天、作者及隔离试用各自既有限制继续有效。
- 第一阶段不增加日常回复调用数，不扩大 4000/6000 字节卡片上限。分析输出按阶段分配容量，避免为了更丰富档案把原始材料塞入单次大请求；具体每维数量和输出参数通过小样本决定。
- 所有分析、合并、生成、评审和一次修订在开始前计入调用计划。聊天通常 16 次、写作通常 12 次仍是已有工程目标，当前配置上限不等于保证；增加多轮实验必须单独规划，不能暗中突破上限。
- 计算示例仅供核对：3 次分批分析 + 1 次合成 + 开发侧 2 个版本各生成 2 轮（4 次）+ 1 次评审 + 1 次修订 + 留出侧 2 个版本各生成 2 轮（4 次）+ 1 次评审，共 15 次。此例不含合并，不代表覆盖全部情境或通过多日验收；实际计划按材料重新计算。
- 原文、原句证据、真实留出答案，以及含这些内容的临时输入/输出和缓存在任务终态清理，不在日志、诊断或测试报告中变相长期保存。隔离试聊/试写演示沿用现有受限展示与清理规则，不新增个人评测全文长期库；保留概括规则、定位、覆盖、配置和验证摘要，真实个人数据不入 Git。
- 原文清理后，可对已有结果运行新的合成情境检查；补充来源分析、重建更深档案或复核原文需要重新上传。不能从旧短卡恢复未保存的原始信息。
- 不自动迁移或替换已应用版本；新档案与新候选沿用保存、明确应用和版本恢复路径。恢复旧版本不等于重新通过新评测，手写修改保留未验证状态。
